# skill-craft-charter：编写 skill 的宪章

> 按需载入：第一性原理与信源见 `references/理论基础.md`；落地步骤与张力清单见 `references/方法论.md`。正文只放铁律与核心条款。
> 技能分工（本宪章是「编写原则」入口，其余环节各有其位）：**流程**走 `guide-dev`（九步/轻量闭环）；**审查**走 `adversarial-review`（独立子审查者）；**编码/乱码**走 `charset-pitfalls`（写文件前过闸门）；**安装/备份**走 `skill-install-ops`。

## 0. 铁律（缺失即违规，四条）

1. **研究先行**：动笔前先搜索权威信源的前沿信息——**多角度**（论文、官方文档/文章、权威人士的一手、及时、实质性内容、**已有类似 skill/meta-skill 成品——含 GitHub 开源**），综合分析并沉淀为「理论基础 + 方法论」两份工作稿，再开始写。凭记忆、凭模板直接写 = 违规。
2. **实事求是**：可核实处给出处；无法核实或不确定处如实说明；失败诚实标记并保留原文；不编造、不讨好。只写当前最佳行为（present tense、不写「不再用 X」式历史否定），会漂移的事实指向活权威（live authority，如 --help/模型清单/live schema）并注明用前重验（**采集命令＋实测日期**，缺一不算注明）。**稳定不变量**（如「索引覆盖全部活日志」）可留正文；**会漂移的数字**（计数／体积／行数／版本／路径）旁注采集命令＋日期，或下沉 references/ 台账。**自述可核（判定句）**：凡写「已把 X 改为 Y」（含交付说明与本技能正文），须同时给出**可复验锚点**（文件:行号 ＋ 复跑命令，或改动前后哈希），并在同一轮以实物复验一次；**不得在未复验时写「已改」**——「自述与实物不符」属**必改项**，不受「只修阻断/严重」限制。
3. **目标先于动作**：未确定「产出什么 + 可观察完成判据」不得动手，**判据须先落盘再写产物**（可观察：判据文件的落盘时间早于任何产物文件；若同批落盘，须在任何产物写入前先落判据并留基线）；判据必须可观察、可失败（恒真/空集 = 假绿灯）。
4. **自我一致**：宪章约束一切 skill，包括它自己——任何 skill 若违反本宪章，它本身就是反例；任何「为达到目的」新增的约束，须先通过删减测试（见 §4）。
> **归类口径**：可执行规则见 §4（**归类仲裁句**「判不准按计入」＋每命名空间上限）；§0 四条归「通用」组。

## 1. 第一性原理（编写前先还原到根）

> **管道判据**：把 skill 想成**给水流定形的管道**，而不是一本操作手册。
> 三种失败对称：**太短 → 挡不住，行为四散漏水**；**太绝对 → 管壁太硬太窄，阻力与流量代价都大，遇边缘情形即僵死**；
> **太长 → 模型负担上升、忘记管道存在，规则形同不在**——这是**总量**问题，不是「变长即错」：
> **若变长换回了更高价值就保留；否则先删啰嗦/冗余/消极段落、合并重复、重写压缩，再谈新增**；目标是**总量不增而信息质量升**。
> 故设计目标是**在正确方向上取得尽可能大的可行域**：
> **红线（禁止）必须绝对**——它是管壁，不可商量；**方向（判据、取舍、优先级）要给足**——它决定流向；
> **方法与步骤只给到"足以复现"为止**——再细就是替模型写决策树（§1.4），既增阻力又降泛化。
> 自问一句即可判：**这一句是在定管壁、定流向，还是在替模型走路？** 第三种删掉或外置。

> 全文与信源见 `references/理论基础.md` §一。这里只给**结论锚点**（每条一句结论，是对应推论的摘要；推理过程与信源等细则只在 理论基础）。

1. **模型是概率推理引擎，不是确定性程序**：skill 的价值是「在正确时点塑造注意力」。约束必须可观察、可被否定；「你要认真/尽量/重视」这类不可证伪措辞一律拒绝。
2. **上下文 = 有限注意力预算**：token 越多、注意力越稀释（context rot）。每条新增条款都要证明「买回的行为收益 > 它的 token 成本」。
3. **泛化优先，少即是多**：几乎所有知识来自预训练；skill 只规范「接口/风格/边界」，不灌输领域内容。越写越长、越具体的条款反而损害泛化。
4. **正确海拔（right altitude）**：每条条款落在「具体到可执行」与「抽象到可泛化」之间——给模型一个**启发式**，而不是替模型写死决策树。
5. **不可判定 → 转可判定**：凡「猜不准」的问题（编码、意图），正确性不建立在「猜得准」上，而建立在「可证无损/可验证」上。
6. **约束哲学随 skill 性质而变**：工程型用可观察判据＋铁律＋闸门；判断/创作型给知识底座＋启发式清单，并明示「意图优先于字面」。**措辞形式须匹配失败类型**：「跳过规则」用禁止句，「输出形状错」用正面契约；不加豁免小句。

## 2. Agent 系统控制论（编写即设计一个反馈回路）

> 全文见 `references/理论基础.md` §二。

skill 是一套**外层控制器**，面向一个**冻结模型**设计。四要素缺一不可：

- **设定值** = 任务目标 + 可观察验收判据（先定目标再动作）。
- **执行器** = 模型按 skill 产出。
- **传感器** = 可观察判据 + 独立审查（**观测独立性**：审查者不得看作者的推理与结论）。
- **控制器** = 只修「阻断/严重」，轻微/建议归档；反馈只审增量，直到收敛或熔断。

关键性质：**可观测性**（判据可失败；假绿灯 = 传感器失效；「跳过即通过」是最危险自欺）、**自适应**（档位分级：免审/轻档/重档、轻量↔九步，控制强度随风险缩放而非一刀切）、**信号/噪声区分**（条款生命周期 trial→active→淘汰，零证据降权）。

## 3. 张力冲突与消解（写之前先列张力对）

写之前先把遇到的张力逐条列出；每对张力须有消解方式，否则按 §4 删条款。张力清单见 `references/方法论.md` §三。

## 4. 约束最小化与「删条款终局」（本宪章核心）

**无法消解张力冲突时，减小或删除条款约束，而不是继续加约束。**

「发现问题 → 加一条条款」是条款膨胀机制，造成恶性循环：文字越多 → 注意力越稀释 → 越抓不住关键 → 只能再加条款。**终局策略是反向做减法**（机制见 `references/方法论.md` §四）。

计数口径：「条款」＝**带判定句或禁止句的独立编号项**，与所在节号无关（节名可改编号、可改名，计数单位不变；纯解释、操作、惯例与自检清单项不计入）。命名空间维度另计：**每个命名空间 ≤4**，超限时新增须先在该命名空间内**淘汰等量**（上限「通用 ≤10 ∧ 每命名空间 ≤4」为本机参考值，机制核心是「到上限先淘汰等量」）。
「命名空间」＝**主题分组**（本宪章用 regulation/document/code/general 四类，或 skill 自声明的同义分组；未声明的按「通用」计）。**归类仲裁句**：① **原理/解释节**的编号项（如「第一性原理」的结论锚点）**不计入**条款数——即使其中含义务语气；② **任何节内以独立编号列出、且自带判定句或禁止句的项计入**（如「铁律」「硬性条款」）；③ 判不准时**按计入处理**。

## 5. 结构惯例

- **frontmatter**：**必需** `name`＋`description`（后者是**主要触发机制**）；官方字段表**没有 `version`**——它是本机配套约定（供安装器比对），建议填写，其它宿主可能忽略。`description` 内嵌触发词：只写「何时触发」＋一句话「做什么」，**流程步骤留给正文**；触发短语要**具体**（枚举字面短语＋「Do NOT use for…」负向边界）。**平台专属字段**（如 `agent_created`）外置到适配层。
- 正文骨架（顺序可按 skill 性质调整）：**原理（冲突时回到这里）＋ 铁律/硬性条款（每条带可观察判定句）＋ 分层/例外出口 ＋ 自检清单**；本宪章按「铁律 → 原理 → 控制论 → 张力 → 删条款 → 自检」排布。
- **外置判据**：一个二分问题——**把这段删掉或移到另一个文件，本次执行会不会变？** 会变＝载荷留正文；不会变＝**维护记录，必须外置**（一律外置者：版本历史、实战与踩坑记录、实测台账、设计理由与替代对照、审查留痕）。
  **阈值（触发复核，不是硬门）**：**>500 行**（官方规范 Level 2「Size: <500 lines ideal」）或 **>12000 字符**（中文以字符为准；**行数与字符数均整文件计，含 frontmatter**）任一命中即触发复核。
  **钩子三态**（外置后必须留其一，各带触发条件）：① 指针（该节相关时读）；② 触发词（命中即读）；③ 摘要（≤5 行；单段 <1200 字符 或 全文 <8000 字符时用）。**没有钩子＝外置等于删除**。
- **术语边界**：本宪章不使用与全局记忆同名的结构称谓。「渐进式披露／外置判据」**不得**称为「三层分工」（后者在 `~/.dsh/AGENTS.md` 中专指规则 0/1/2）；引用来源须写明 `文件名+节号`。
- **体量口径**：以**字符数**为主，行数仅作提示（中文每行字符量数倍于 ASCII）。实测值用 `python scripts/measure_skill_sizes.py` 现取。
- 踩坑速查独立成节：正文只留「症状 → 判据 → 处置」一行式，复现过程与原始报错外置。
- **版本升级单位**：凡改变**用户可见行为**（触发词、参数取值域、错误码、输出形状、提示语）**必须升版**；纯措辞更正不升版。

## 6. 自检清单（编写后逐条核对）

> 本节是**启发式核对**：各项给「该检查什么」与判定要点，**不展开完整做法**。**清单按执行顺序排列**：第 1–2 项是**动笔前**条件（判档、工作稿先落盘），第 13 项是**写出产物前**的生成闸门。**每条须附与该项相称的可复跑证据锚点**（命令输出／文件:行号／哈希；位置见 §7），**未标注即视为未执行**。

- [ ] **改 skill 前判档**：前置闸门；判档结论与理由写入交付首段；**改宪章自身、删条合并、下游可见行为变更**不得判为免审；档位委托 `guide-dev` §2B.0。
- [ ] **研究先行**：两份工作稿已落盘且**早于**所有交付文件；核心论断各有可追溯信源（论文／官方文档／一手内容／同类成品仓库之一），**未混入泛化词**。
- [ ] **先跑判据**：先运行所有可执行判据脚本，以输出为准——「看起来对」不算证据；脚本只证**运行行为**，**不替代**本清单**任何一项**（含编写期条款是否通过删减测试）。
- [ ] **条款合格**：每条有可观察判据、无不可证伪措辞、通过删减测试；**张力逐条均须显式列出**并已消解，无法消解者已删条款。
- [ ] **逐条扫义务**：把正文每一条义务拿去**全树搜索**，确认既有陈述、又有落点；**搜不到的即为丢**（压缩后尤其要做）。
- [ ] **数字溯源**：凡正文出现数字，须能当场复算或指向台账；**算不出的删掉或外置**。
- [ ] **体量与钩子**：正文未超阈值；维护记录类内容均已外置且**留有钩子**（指针／触发词／摘要）。
- [ ] **总结专章**：位于正文最末、行数占正文 ∈[3%,8%]（或已按豁免条件记明理由）。
- [ ] **触发词与交叉引用**：触发词收窄到「命中即应载入」的最小集；`description` 内嵌触发词与负向边界；正文 `§X`／文件名指针**无断链**。
- [ ] **反向扫噪声**：搜日期戳、内部编号、修订标记、「见／详见／依据」括注——**这些是作者的记录，不是读者的信息，删**。
- [ ] **当读者重读**：只问「照着做能否直接执行」；需回头查别处才能懂的句子，改写或外置。
- [ ] **证据与引证**：引证目标真实一致；引用统计须区分**取数语句**与计数语句；备份须含**改前基线**（确无基线须声明）；脚本入 `scripts/` 或归档并写明位置；**交付清单与磁盘一致**；**自述可核**（称「已改 X」须给锚点并同轮复验）；正文／`_meta.json`（技能根，其 `version` 须与 frontmatter 同源）／台账／磁盘**四者互核**，任一处不符即必改项。
- [ ] **生成闸门**：正式**写出产物前**（受检对象＝**草稿态实物**），先按本清单出**简洁自检报告**（逐项一行：结论＋证据锚点），**各项核对无误再写产物**；跑生成器属「写出」的一部分，送审基线在其后冻结（见下项）；报告不得只写「已检查／无误」。
- [ ] **审核时序**：送审基线在**跑完所有生成器之后**冻结；复审只审增量。
- [ ] **审查**：至少一次**独立**审查（独立子审查者、只喂必要数据——**不得喂作者推理与结论**；详见 §2），阻断/严重清零。
- [ ] **撤回就地**：作废结论时回到**每一处**生效段落就地标注或删除。

## 7. 交付与资源指引

> **读法分工**：**构建期**＝写**任意** skill 时按需载入（宪章的依据与步骤）；**维护期**＝只维护本宪章**自身**时才读（设计理由、自证、机器数据、自身留痕）。

- 【构建期】`references/理论基础.md`：第一性原理 + 控制论 + 权威信源（含 URL）。
- 【构建期】`references/方法论.md`：研究→综合→设计→编写→审查 的落地步骤 + 张力消解完整清单 + 删条款终局 + **留痕规则**（写在哪里、记到什么粒度）。
- 【维护期】`references/专章依据.md`：总结专章的位置与篇幅依据；**其 §二 是「总结专章」计量口径（分母、行数定义、换算与反向陷阱）的唯一出处**。
- 【维护期】`references/设计依据.md`：**外置判据**与总结专章的**工作稿**（筛选判据、替代对照、改口留痕）。
- 【维护期】`references/归类口径与自证.md`：§0 归类口径的**自证与边界**（字面口径计数、优先关系、不可机检边界）。
- 【维护期】`references/归档台账.md`：**机器数据唯一出处**（归档清单/计数、脚本哈希、体量实测、**判据复跑命令**）。
- 【维护期】`references/自维护留痕.md`：本宪章**自身的留痕**（留痕清单、案例台账、历轮改动与审查留痕、回滚点）。
- **总结专章**：全文较长时，在**正文最末**（资源索引之后）放一节「## 总结（要点复述）」，把关键硬约束再说一遍——末位注意力最强（依据：Critical Instruction Repetition，见 `references/理论基础.md`）。
  ① 只复述**硬约束与不可逆后果**；不复述历史、案例、台账。
  ② **逐字复制**原条款或**显式指回**（「见 §X」）；**不得改写**（措辞漂移会被当成冲突约束）。
  ③ 篇幅＝**占正文行数的 3%–8%**（下限防「写了等于没写」，上限防注水）；**不得用绝对字数**。
  ④ 分母含专章自身；换用其他分母须换算（细则见 `references/专章依据.md` §二）。
  ⑤ 正文 <3000 字符或硬约束 <5 条时**可豁免**，并在交付首段写明理由；门槛判不准时按「不豁免」处理。
  ⑥ **可失败判据**：专章行数占比 ∈[3%,8%]，且每条能在正文找到逐字对应或 `§X` 指针。
- **交付披露义务**：交付说明须含一条「**与预期量级偏离最大的指标**」（体积／耗时／成本／覆盖率）＋真因＋是否可优化，不得等对方发现再解释。
- **长期核对**：每完成 5 个 skill（或每季度）由**非作者**对宪章做一次「§5＋§6」独立核对。

## 总结（要点复述）

1. **研究先行**（§0.1）：动笔前先搜多角度信源（含同类成品）并沉淀两份工作稿，**先落稿再动笔**，不凭记忆或模板直写。
2. **实事求是**（§0.2）：「**自述与实物不符**」属**必改项**，不受「只修阻断/严重」限制；会漂移的数字须带采集命令＋日期。
3. **外置判据**（§5）：删掉它本次执行若不变，就必须外置并**留钩子**；版本历史、踩坑记录、台账、审查留痕一律外置。
4. **条款与见证**（§4／§6）：张力无法消解时**减条款**而非加条款；自检须逐条留痕，**不得**由运行时脚本替代，未标注即视为未执行。
