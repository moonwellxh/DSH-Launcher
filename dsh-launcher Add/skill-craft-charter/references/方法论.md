# 方法论：编写 skill 的落地步骤

> 条款的**依据案例**（编号定义见 `references/自维护留痕.md` §二 案例台账）本文件**不逐个挂**——需要溯源时读该表。
> 本文件是 SKILL.md 的可执行展开。SKILL.md 给「是什么/为什么」（铁律+条款），本文件给「怎么做」（步骤+张力消解+删条款）。

## 一、总流程（研究 → 综合 → 设计 → 编写 → 审查）

1. **研究先行（多角度）**：搜索权威信源前沿信息——论文、官方文档/文章、权威人士的一手、及时、实质性内容、**已有类似 skill/meta-skill 成品（含 GitHub 开源）**四路并行；记录每条的 URL 与核心观点。**两份工作稿（理论基础／方法论）须在任何产物文件之前落盘**——可观察判定：工作稿的 mtime／首个备份基线早于所有产物；若同批落盘，须先落稿并留基线。
   - 信源先分级（一级权威官方／二级可靠期刊与官方文档／三级参考博客论坛／四级存疑匿名），优先一级；开放问题先沿分类轴枚举维度再逐维检索，防过早收敛（查到第一条就停 = 遗漏）。
   - 核心事实做 CoVe 四步验证：分解声明 → 规划验证 → 独立验证 → 修正输出（未验证/矛盾的删除或改「未能确认」）。
   - 行为基线先行：写/改前先跑无 skill 的 baseline 压力场景，逐字记录模型违规，条款只针对已观测到的违规（源：obra/superpowers writing-skills）。
   - 生成期导引单：**编写开始之前**先按 `adversarial-review` §0.3 取前置导引单（`guide_inject.py` 计算，禁手写截断）并在动笔前留痕。
   - 成品蒸馏：对已有类似 skill 走五步——蒸馏原则 → 分析核对归因（信源须实网核验其存在性，URL/arXiv/仓库名逐一可核，防虚构/错归因）→ 挑选（只取「补充非替代」的缺口）→ 归并（update over create，见 §三.4）→ 改造套入自身框架，禁止整仓照搬。
2. **综合沉淀**：把信源 + 自身经验综合为两份工作稿——`理论基础`（第一性原理+控制论+信源）与 `方法论`（步骤+张力消解）。
3. **设计**：先列张力对（见 §三），定「铁律」「核心条款」「例外出口」「自检清单」四层；判档（免审/轻档/重档；轻量↔九步）。
4. **编写**：SKILL.md 只放「缺失即违规」的铁律+条款；细则下沉 references（指针+触发词接入）。每条条款带可观察判定句。按操作脆弱度选规定性——精确计算（公式/单位/rounding/日期边界）强制脚本化，禁止用文字让模型脑算。**同一契约的默认值、取值域、语义说明不得在正文与代码／`--help` 中各写一份**：能由代码或帮助文本产出的，正文只写「见 <命令>」。
5. **审查**：独立子审查者分级审查（阻断/严重清零），复审只审增量；未过回到第 4 步。**基线必须覆盖可执行产物**：改动含代码/脚本/数据的，备份清单须含其改动前副本；确无基线时，须在送审说明显式声明「该文件无基线，只能行为判定」并据此重估该项的可关闭性。**发起审查时须把本宪章（§5 结构惯例＋§6 自检清单）与 `guide-dev` 的相关规范一并列为审查依据**，并在请求中写明「逐条核对」，不得只让审查者看到技能目录里的一行 description。文本审查之外补**运行时评估（eval-as-code）**：配可运行评估集，测「该触发时是否触发、不该触发时是否远离」（触发双向 + pass rate/执行时间/token；源：Anthropic《Improving skill-creator》、Red Hat《Building skills you can trust》）。
5b. **断言纪律（L0/自检脚本）**：断言取**不变量**而非常量——禁止把当前语料规模/当前计数写进期望值；凡与**非稳定对象**（活日志、活动会话、网络）比对，改写为「不得出现某类改变」的绊线并注明适用边界；**假 FAIL 与假 PASS 同属传感器失效**。负向对照用的「必不存在」样本须**运行时生成**，不得以字面量写入会被本工具索引/采集的语料。
6. **反哺（发布后）**：让 agent 在真实任务中把成功路径与常见错误写回 skill，从事后观测发现「实际需要什么上下文」再迭代收敛（源：Anthropic《Equipping agents for the real world with Agent Skills》）。

## 二、档位分级（自适应控制强度）

| 档 | 适用 | 审查强度 |
|---|---|---|
| 免审 | 只读/可回退/一次性答复/临时草稿 | L0 确定性检查（编码+结构+实跑） |
| 轻档 | 纯文本 ≤5 文件、无跨模块契约 | L0 + 一次精简独立审查 |
| 重档 | 契约变更（SKILL.md 触发词/契约）、不可逆副作用、多机分发 | L0 + 独立子审查者（首轮+复审）+ 只修阻断严重 + 快照沉淀 |

判档四量：持久化 × 被后续依赖 × 错误代价（含不可逆） × 是否已被确定性检查覆盖。

## 三、张力冲突与消解（完整清单）

> 写之前先把遇到的张力逐条列出；每对张力必须有消解方式，否则按 §四删条款。

1. **约束 ↔ 泛用/不束缚模型**
   - 消解：只约束「达到目的所必需」的最小集；给原则与触发条件，不穷举边界 case；留例外出口。
   - 例外出口四要素：偏离哪条 / 为什么 / 影响面 / 替代观测。
2. **文字堆砌 ↔ 约束收紧**（最核心的恶性循环）
   - 消解：单一事实源 + 指针+渐进式披露（细则按需载入）+ 条款数上限 + 生命周期淘汰。
3. **全量审查 ↔ token 成本**
   - 消解：对象=本次增量；复审只审增量；档位分级；L0 确定性脚本零模型判断；脚本复用不重写。
4. **单一事实源 ↔ 复述**
   - 消解：正文只写指针+触发词；细则唯一真源在 references，禁止两处复述。近重复技能优先合并（update over create），合并后 description 须 broaden 覆盖全部能力。
5. **自我确认 ↔ 客观**
   - 消解：独立子审查者（新建、不 fork 上下文、只喂必要数据、不喂作者推理/结论）。
6. **条款互斥**（如「详尽 vs 脱敏」）
   - 消解：一条显式优先级仲裁句（「H10 优先，脱敏后类型/量级即算要素」），不堆第三条。
7. **防架空 ↔ 防束缚**
   - 消解：合并仲裁——如「正则收严 + CI 实测退出码」同时满足两方。
8. **诚实降级 ↔ 静默覆盖**
   - 消解：弹选+留痕；未选择不产出，禁止静默改走。
9. **猜测（不可判定）↔ 正确性**
   - 消解：转可判定检查（可证无损/可验证），见理论基础 §一.5。
10. **触发词收窄 ↔ 欠触发防漏**
   - 消解：触发词枚举**字面短语**（不抽象表征），因模型默认欠触发；用「Do NOT use for…」负向边界防误触，而非删掉核心字面短语。

> §5 骨架中的「自检清单」指**过程见证物**，不得解释为「可用运行时脚本替代」；判定见 SKILL.md §6「先跑判据」项。

## 四、删条款终局（无法消解张力时）

> 触发：某张力无法用 §三 任一机制消解，且继续加约束只会让条款越堆越紧。

执行（反向做减法，按序）：

1. **删减测试**：逐条问「删掉它会坏什么？」——回答不出可观察后果的，删除。**本条只裁「条款」**；自检清单项的增删不适用本条，须先出「改前逐条 → 改后落点」映射表，映射不出的条不删（判据与教训见 `references/自维护留痕.md` §三 末）。
2. **准入测试**：只保留「缺失即导致每会话违规/跑偏」的行为约束。
3. **下沉**：不是删除而是「转指针」的，下沉到 references，正文只留触发词。
4. **上限淘汰**：到条款数上限（通用 ≤10 ∧ 每命名空间 ≤4，本机参考值，计量单位与「命名空间」定义见 SKILL.md §4 计数口径段），新增必须先淘汰等量。
5. **生命周期淘汰**：trial 条款无真实返工证据 → 不转正；active 条款连续零证据 → 降权 → 淘汰。
6. **合并**：多条同主题条款合并为一条宽而有力的总则（依据见 理论基础 §一.3）。

> 同 SKILL.md §6，此处不重复；逐条给出可观察证据，不用「我觉得没问题」结案。

## 六、编写证据（留痕规则；本宪章自身的台账已外置）

> SKILL.md §6 规定「每条须留痕」，本节规定**写在哪里**与**记到什么粒度**。本宪章**自己**的留痕（留痕清单、案例台账、历轮改动与审查留痕、回滚点）在 `references/自维护留痕.md`（【维护期】文件）。

1. **位置与形式**：工作稿与设计依据入 `references/`；实测机器数据（计数／哈希／体积）入台账；逐轮改动与审查留痕入维护留痕文件；**交付首段须注明位置**。锚点形式＝命令＋输出，或 `文件:行号`＋哈希（**行号只在同一轮内有效**，跨文件/跨轮一律改节号或可 `grep` 的锚点字符串），或**改动前后 SHA256**。
2. **粒度**：纯文档措辞与自述数字更正——记一行日期＋原因，**不升版**；凡改变下游可见义务（触发词、契约、指针）者**必须升版**并记理由。
3. **无法给出证据时**：显式标注「**不可机检·自评**」并给出**可替代物**——**未标注即视为未执行**。
4. **长期核对**：每 5 个 skill（或每季度）由**非作者**对宪章做一次「§5＋§6」独立核对，结论带日期＋SHA256 写入 `references/自维护留痕.md`。
