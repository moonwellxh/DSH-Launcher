## 二、第一性原理分析（文字该不该留在正文）

宪章 §1.2 已确立：上下文＝有限注意力预算，目标是「最大化期望结果所需的**最小高信号 token 集**」。据此对正文做**筛选判据**推导：

1. 正文的**唯一职责**是在命中的那一刻改变本次执行（决策、铁律、闸门、问法映射）。
2. 任何**不改变本次执行**的文字，都是纯成本——它稀释信号、且不买回行为。
3. 故判据＝**删减测试的镜像**：「这段话删掉（或移到另一个文件），本次执行会不会变？」
   - 会变 → 留正文（这是载荷）
   - 不会变 → 外置（这是**维护记录**，只对**下一个维护者**有价值）
4. 据此，**版本历史、实战/踩坑记录、实测台账、设计理由、审查留痕**全部属第 3 条第 2 类：运行时零价值、维护时高价值 → **应外置**。
5. 控制论视角（宪章 §2）：正文＝控制器在**决策时刻**的状态；维护记录＝**离线**信息。把离线信息常驻控制器，等于让每个会话都为「上一位作者的记账」付费。

**结论**：需求 1 不是新原则，是 §5「references 分工」的**判据化与阈值化**——原条款只说「细则下沉」，没给**筛选判据**，也没给**触发阈值**，导致长技能（如本机 `skill-install-ops` 27.8 KB、版本历史占 1/5）不自知。

## 三、第二性原理分析（末尾复述该不该做、怎么做）

1. 证据 S1：长上下文的中段**检索**最弱，且**检索失败直接导致推理失败**。→ 若关键约束埋在正文中段，等于把它放在最易丢失的位置。
2. 证据 S2：首/末位对**非推理模型**的合规率有实测优势；末端复述利用新近偏差。
3. 但 §1.3（泛化优先）＋S2 的反噬三条给出**硬边界**（一手 FAQ 逐字："Yes, in **three** ways."——该三条＝FAQ 那三条；「推理模型」条在**同页另一列表**「When this backfires」（**四条**）里，**不在** FAQ 三条内。两列表分属、**均成立**，详见 §七）：复述**不能泛化到所有条款**，否则优先级信号归零、且与「越写越长损害泛化」同向互斥。
4. 消解（宪章 §3 张力对）：把「复述什么」限定为**硬约束＋不可逆后果**，把「复述长度」限定为常数级（~~≤3 条／≤200 字~~ **已作废**，见 §七：现行＝占正文行数 3%–8%），把「谁复述」限定为正文已载明者且**逐字或显式指回条款号**（防 S2 的「首尾措辞不一致被当冲突」）。
5. 故需求 2 的**正确形态**是：**末位高信号锚点**（~~3–5 条~~ **已作废**，见 §七：现行＝复述硬约束、篇幅按行数百分比），不是「把正文再讲一遍」。需求 2 的字面读法（「重复重点要点」）若无边界，就会变成正文膨胀——这属宪章 §4 要防的膨胀机制，必须给出反膨胀闸门。
