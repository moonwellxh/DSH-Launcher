## 一、第一性原理（还原到最根本约束）

### 1. 模型是概率推理引擎，不是确定性程序
- 推理：skill 的条款不是「会确定性执行的代码」，而是对模型输出分布的一次条件化。因此 skill 的价值是「在正确时点塑造注意力」，而非「保证行为」。
- 推论：约束必须**可观察、可被否定**；无法验证的条款（"要认真""尽量做好"）既不能作为传感器信号，也无法被证明有效。
- 源：本机经验——charset-pitfalls「验收只看能解析/退出码」失败模式；adversarial-review M6「条款文本须可客观检验，不可证伪措辞确定性拒绝」。

### 2. 上下文 = 有限注意力预算（context rot）
- 推理：transformer 的注意力随长度稀释，token 越多、召回越差（"context rot"）。每写一个字都占用注意力预算，都在稀释其它条款的信号。
- 推论：目标是「最大化期望结果所需的**最小高信号 token 集**」。每条新增条款都要证明「买回的行为收益 > 它的 token 成本」。
- 源：[Anthropic《Effective context engineering for AI agents》(2025-09)](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)

### 3. 泛化优先，少即是多（Superficial Alignment）
- 推理：LIMA 实验表明，几乎所有知识来自预训练；指令微调只需教会"风格/格式"，而非灌输内容。长而具体的条款反而损害泛化。
- 推论：skill 只规范「接口/风格/边界」，把领域知识留给预训练能力与 references；不做百科式 skill。
- 源：[LIMA: Less Is More for Alignment (2023)](https://arxiv.org/abs/2305.11206)；[Anthropic《Claude's Constitution》](https://www.anthropic.com/news/claudes-constitution)——明确记录（转述）：越写越长、越具体的条款会降低泛化，一条宽总则反而最好。

### 4. 正确海拔（right altitude）
- 推理：系统提示有两种对称失败——hardcode 脆弱的 if-else（fragile）与过度模糊（假装共享上下文）。最优落在中间：足够具体以引导，足够灵活以留给模型强启发式。
- 推论：每条条款做一个二分测试：**这条是给了模型一个启发式，还是替模型写死了决策树？** 后者删除。
- 源：同上 Anthropic context engineering；本机实例——cafa-art-mentor 明示「条款间若出现张力，以一位真实的好老师此刻会怎么做为最终裁决，意图优先于字面，判断优先于执行」。

### 5. 不可判定 → 转可判定
- 推理：很多正确性问题不可判定（如"这文件什么编码"——同一字节串可同时是合法 GBK/Latin-1/UTF-8）。正确性不能建立在"猜得准"上。
- 推论：正确性建立在**可证无损/可验证**上；把不可判定问题改写成可判定检查（如编码：按同一页写回则字节不变）。
- 源：本机经验——charset-pitfalls G0 三段式闸门。

### 6. 约束哲学随 skill 性质而变
- 推理：skill 分两类——确定性/工程型（编码、日志、解析、安装）与判断/创作型（点评、教学、风格）。前者的错误可枚举、可观测，适合硬约束；后者的好坏多维、意图性，硬约束会杀死判断力。
- 推论：确定性 skill 用可观察判据＋铁律＋闸门；创作型 skill 给知识底座＋启发式清单，并明示「意图优先于字面，判断优先于执行」——清单是启发式，不是逐条核对。
- 推论（形式匹配失败）：禁止句只对「跳过规则」型失败有效；「输出形状错」应给正面契约（说清输出是什么、按什么顺序），禁止句在此类场景会反噬（模型与「don't X」谈判）；任何豁免小句都会重开谈判，故「no nuance clauses」。
- 源：本机实例——coding-log-monitor（H1-H23 硬性条款每条带「判定」句）对照 cafa-art-mentor（明示「条款间若出现张力，以一位真实的好老师此刻会怎么做为最终裁决」）；外部印证见 §一.4「正确海拔」（Anthropic）——本原则是其按 skill 性质的具体化；prohibition 反噬为 obra/superpowers writing-skills 的经验结论。

## 二、Agent 系统控制论（skill = 外层控制器）

### 控制回路（四要素）
```
设定值(目标+可观察验收判据) → 执行器(模型产出) → 传感器(可观察判据+独立审查)
        ↑                                                    ↓
        └──────── 控制器(只修阻断/严重) ← 反馈(复审只审增量) ←┘
```
- skill 是一套**外层控制器**，面向一个**冻结模型**设计；被控变量是「上下文组装」本身（提示模板、few-shot、检索深度、规划/验证轮次），而非工具选择。
- 源：[《Context Assembly as the Controlled Variable》(arXiv:2607.25408, 2026)](https://arxiv.org/abs/2607.25408)——稳定性定义为「有界策略变化下的非递减期望收益」；该文报告了控制器置信度对实测结果的不确定性校准分析。「规则要小而可枚举」是本宪章据此推断，非论文原文主张。

### 关键性质
1. **可观测性**：判据必须可观察、可失败。恒真/空集给 1.0/短路断言 = 假绿灯 = 传感器失效。「跳过即通过」是最危险自欺（本机经验：fire-check-consolidation）。**双向失效**：与非稳定对象（活日志／活动会话／网络）比对，或把当前计数写死为期望值 → **假 FAIL**；假 FAIL 与假 PASS **同属传感器失效**，且它训练出「忽略红灯」的习惯。
2. **可控制性**：只修「阻断/严重」，轻微/建议归档——否则控制成本爆炸。
3. **稳定性/收敛**：复审只审增量 + 收敛重合度 ≥0.80 + 熔断上限（超 5 轮交人裁决）。
4. **自适应**：档位分级（免审/轻档/重档；一次性/MVP/生产；轻量↔九步升降级）——控制强度随风险缩放，而非一刀切。
5. **观测独立性**：传感器不得被执行器污染——审查由独立子审查者执行，只喂必要数据，不喂作者推理/结论。
6. **信号 vs 噪声**：条款生命周期 trial→active→淘汰 + 零证据降权 + 反自我强化（同源污染不可当有效性证据）。
- 源：控制回路源自本机 guide-dev/adversarial-review 技能；自省纠错回路见 [ReAct / Reflexion](https://lilianweng.github.io/posts/2023-06-23-agent/)。

## 三、约束与规则的收敛（为什么「越堆越紧」是病）

1. **补偿式条款膨胀**：Anthropic 明确指出「模型出现不想要的行为 → 就加一条条款」极容易，这本身即膨胀机制；宪法既非定稿也非最优，靠试错迭代。
   - 源：[Claude's Constitution](https://www.anthropic.com/news/claudes-constitution)
2. **规则可治理性**：权威性应来自「显式、可读、可改」——条款必须能被定位、审查、修改；否则与隐式偏好一样无法治理（「可定位/可审查/可修改」为本宪章外推，CAI 原文是对照显式原则自我批判再修订的训练方法）。可借鉴「每条条款写明它要抑制/促进什么可观察行为」。
   - 源：[Constitutional AI (2022)](https://arxiv.org/abs/2212.08073)
3. **宪法漂移**：长期暴露下价值观会缓慢侵蚀，需定期检测——检测机制＝SKILL.md §7「长期核对」（每 5 个 skill 或每季度一次，核对者不得为宪章作者，结论写入`references/自维护留痕.md`并带日期＋SHA256）。**只有漂移结论、没有检测机制 = 该条未落地**。
   - 源：[Constitutional Drift (Zenodo 预印本，权威性待验)](https://zenodo.org/records/21234231)
