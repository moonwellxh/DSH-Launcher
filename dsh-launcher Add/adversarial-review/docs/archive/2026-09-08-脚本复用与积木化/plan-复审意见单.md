## 〇、结论摘要（是否可进入步骤 7）

**结论：plan 可进入步骤 7（编写具体代码块）。** 上轮 3 条严重（S1/S2/S3）均已正确闭合；未引入新阻断/新严重。

- **S1 已闭合**：WBS-4.1 补齐「代跑前查任务级 registry」+「① 已晋升→技能级 hits+1 / ② 未晋升→reused_scripts[]（§4.5 产端）」两分支，与 spec §5 W6（spec 行 160）逐字对应；产端归属节点明确（WBS-4.1 产 reused_scripts[]，WBS-4.2 序列化进快照 reuse_ledger）。
- **S2 已闭合**：WBS-5.2 重构为「A 晋升轮 → B 复用轮」两阶段，消除「首轮代跑时技能级无已晋升条目」的时序矛盾——§8#1 的 hits+1 落在 B 轮（该脚本已在 A 轮晋升）；§8#6 的 reused_count≥1 主路径由 A 轮未晋升代跑满足。核心矛盾消除，判定闭合。
- **S3 已闭合**：DAG 增 `4.1→3.1` 边；WBS-3.1 依赖改为 `WBS-2.1 + WBS-4.1`，行为明示「计数数据源=4.1 的 hits」；构建顺序改为 `4.1→(4.2 ‖ 3.1→3.2)`。

**新发现（均为轻微，非阻塞，步骤 7 落码时顺手即可）**：
- w1：WBS-5.2「§8#6 计数>0 由此/**或 B 轮 hits 满足**」的「或 B 轮 hits」表述不严谨（B 轮已晋升代跑 → 记技能级 hits+1，**不**进入 reuse_ledger 的 `reused_scripts[]`/`reused_count`，故 B 轮 hits 并不能独立满足 §8#6）；且 A 轮序列「注册→收集→晋升」未显式含「未晋升代跑」一步，reused_scripts[] 的产时间点靠括号补注而非序列步骤。
- w2：WBS-3.1「同任务≥3 轮」的计数源 c-m4（spec 行 179）为「以快照 round 计数」，而 plan 表述为「计数数据源=4.1 的 hits」——hits 记总代跑次数、不区分轮次，与「≥3 个不同轮次」口径有细微出入；另「跨≥2任务」应读技能级任务维度、round 在 4.2 快照，均非单纯 4.1 hits。因 3.1 准入为设计初值且试点阶段用合成夹具（spec §8#5 诚实口径），真实多任务/多轮计数随沉淀后触发，故仅为口径提示，非阻塞。

## 一、逐条复审判定（S1/S2/S3）

### S1 —— 已闭合（confidence：高）

- **anchor**：plan 行 20（WBS-4.1 关键接口/行为）；对照 spec 行 160（§5 W6）。
- **basis**：spec §5 W6（spec 行 160）规定 `run_registered(name, task_id)`「代跑前查任务级 registry；代跑一次→技能级 hits+1（若已晋升）；未晋升脚本计数记 `reused_scripts[]`」。plan WBS-4.1 现写「**代跑两分支（闭合 S1）**：代跑前查任务级 registry → ① 已晋升技能级：代跑一次→技能级 hits+1；② 未晋升：记入本轮 `reused_scripts[]`（§4.5 reuse_ledger 产端）；误报判定→技能级 false_positives+1」——两分支 + 产端锚点（§4.5）均显式，与 W6 及 §8#1「若该脚本尚未晋升技能级，其复用计入 R7 reused_scripts[]」逐字对应；产端承载节点明确（WBS-4.1 产、WBS-4.2 序列化入快照）。
- **note**：上轮 S1 指出的「reuse_ledger 产端无节点承载」已被 WBS-4.1 分支②承接。本轮未发现该分支与 WBS-4.2（只读序列化 reuse_ledger）之间新增冲突。

### S2 —— 已闭合（confidence：高；附 1 条轻微 w1）

- **anchor**：plan 行 23（WBS-5.2 关键接口/行为）；对照 spec 行 207（§8#1）、212（§8#6）、4.5（spec 行 119–123）。
- **basis**：spec §8#1 的「代跑（hits+1）」以「已晋升技能级」为前提；spec §4.5 的 reuse_ledger 中 `reused_count` 对应 `reused_scripts[]`（未晋升复用），而 W6 明确「已晋升→技能级 hits+1」为另一去向。plan WBS-5.2 现为「**两阶段序列（闭合 S2）**：A 晋升轮——注册脚本→收尾自动收集→S3 晋升（先让技能级有条目）；B 复用轮——再次触发代跑：因已晋升 → **hits+1**（§8#1）；A 轮内未晋升代跑记 `reused_scripts[]`（§8#6 计数>0 由此/或 B 轮 hits 满足）」。此两阶段结构使「晋升」先于「代跑 hits+1」，试点（无已晋升条目）不再出现首轮代跑误判为 hits+1 的矛盾；§8#1 落在 B 轮、§8#6 由 A 轮未晋升代跑满足，二者不再同轮争抢同一批脚本，核心时序矛盾已消除。
- **note**：判定闭合，但括号内「或 B 轮 hits 满足」与 A 轮序列步骤存在表述瑕疵，见新增轻微 w1。

### S3 —— 已闭合（confidence：高；附 1 条轻微 w2）

- **anchor**：plan 行 31（DAG：`└→ WBS-3.1 → WBS-3.2（闭合 S3：3.1 准入计数消费 4.1 的 hits）`）；plan 行 18（WBS-3.1 依赖=WBS-2.1 + WBS-4.1，行为含「计数数据源=4.1 的 hits」）；plan 行 34（构建顺序 `…→4.1→(4.2 ‖ 3.1→3.2)→…`）。
- **basis**：spec §5 W4（spec 行 151）准入「命中计数（跨≥2 任务 或 同任务≥3 轮代跑）」；spec 自证声明④⑤（spec 行 218）hits 写入者=代跑钩子（即 WBS-4.1）。plan 现于 DAG 显式画 `4.1→3.1` 边（`│` 从 WBS-4.1 垂下 `└→ WBS-3.1`），并把 WBS-3.1 依赖改为 `WBS-2.1 + WBS-4.1`、行为标注「计数数据源=4.1 的 hits」。构建顺序由「3.1 与 4.1 并行」改为「4.1 先于 3.1（4.2‖3.1→3.2 在 4.1 之后）」——3.1 不再可能只拿到 2.1 写入的初始 hits=0，S3 缺口（缺依赖边 + 并行误排）已闭合。
- **note**：判定闭合；但「计数数据源=4.1 的 hits」对「≥3 轮」维度口径略有出入（见新增轻微 w2）。因准入为设计初值 + 试点合成夹具口径，非阻塞。

### 轻微（新增，均非阻塞）

#### w1. WBS-5.2「或 B 轮 hits 满足 §8#6」表述不严谨，且 A 轮未显式含「未晋升代跑」一步
- **anchor**：plan 行 23（WBS-5.2，括号内「…（§8#6 计数>0 由此/或 B 轮 hits 满足）」）。
- **basis**：spec §5 W6（spec 行 160）「已晋升→技能级 hits+1；未晋升→reused_scripts[]」为互斥两去向；spec §4.5（spec 行 120–122）`reused_count` 对应 `reused_scripts[]`（`"reused_count": 1` 伴 `"reused_scripts":["l0_x"]`）。故 B 轮「因已晋升→hits+1」记的是技能级条目 hits 字段，**不进入** reuse_ledger 的 `reused_scripts[]`/`reused_count`；「或 B 轮 hits 满足 §8#6 计数>0」不成立——§8#6 只能由 A 轮未晋升代跑满足（plan 主路径「由此」正确，次选「或 B 轮 hits」为误）。另，A 轮序列「注册脚本→收尾自动收集→S3 晋升」未显式列出「未晋升代跑」这一步，reused_scripts[] 的实际产时间靠括号补注说明；建议步骤 7 落码时把「未晋升代跑」明确写入 A 轮序列，或将「或 B 轮 hits」删去以免误导。
- **confidence**：中。

#### w2. WBS-3.1「计数数据源=4.1 的 hits」对「≥3 轮」维度口径与 c-m4 有出入
- **anchor**：plan 行 18（WBS-3.1 行为「计数数据源=4.1 的 hits」）；plan 行 31/34（DAG 与构建顺序：4.1→(4.2 ‖ 3.1→3.2)）；对照 spec 行 179（§6 c-m4）、151（§5 W4）。
- **basis**：spec §6 c-m4（spec 行 179）「『≥3 轮』= 该脚本在 ≥3 个不同轮次被代跑（**以快照 round 计数**）」——即「同任务≥3 轮」需按快照 round 区分不同轮次，而 hits（技能级条目）记的是累计代跑次数、不区分轮次（同轮代跑多次 hits 增多次但轮次不增）；且「跨≥2 任务」需读技能级条目的 task_id 维度（WBS-2.1 写入），均非单纯 4.1 的 hits 可覆盖。plan 表述未区分「跨≥2 任务（任务维度）」与「同任务≥3 轮（round 维度）」两口径，统称「计数数据源=4.1 的 hits」略为笼统。鉴于 spec §9 G-001 明确该阈值为设计初值（校准点=首批沉淀后），且试点阶段 WBS-3.1 以合成夹具做机制验证、真实多任务/多轮计数按 plan 行 34「真实计数随多任务/多轮沉淀后自然触发」，故仅为口径提示，步骤 7 落码时按 c-m4 校准即闭合，非阻塞。
- **confidence**：中。
