## 一、定稿规则（R1~R5，owner 已采纳）

**R1 位置**：前置导引单位于**稳定段与易变段的分界处**，即**紧贴用户本轮文字之前**。这是唯一需要记住的位置定义。

**R2 实现分级**（owner 选定 **B 级**）：

| 级 | 形态 | 状态 |
| --- | --- | --- |
| A | 宿主在用户消息前注入**输入侧**固定块（只花输入价、跨会话命中最大） | **不采用**（无宿主钩子，改造收益不值当） |
| **B** | 编排者在**本会话首个生成动作所在答复的开头**输出一次导引单 → 从下一轮起正好落在"用户文字紧前方"，且永不复改 | **采用** |
| C | 写入固定文件，由宿主每轮在输入侧读取 | 备用 |

**R3 禁止**：**禁止把导引单塞进 skill 文本**（技能目录是每轮注入的固定前缀，改它等于击穿所有技能的缓存）。

**R4 变更纪律**：导引单**只在会话之间更新**；会话内只追加、不改写（沿用现行"历史不复改／只追加／不重发"三条）。

**R5 成本口径**：位置优化的经济后果 ≈ **¥0.005/会话**（按 2026-09-05 价目表，500 tok × ¥9/M 输出价；输入侧注入 ≈ ¥0.00005/次）。**不为此牺牲实现稳健性**；宿主钩子若需 > 半天工作量即不做。

**推导依据（第一性原理）**：前缀缓存机制＝"改动前部任意字节，其后全部失效" ⇒ 唯一正确的排法是**按稳定性降序**：`[系统/技能目录/AGENTS] → [导引单] → [累积材料] → [用户文字] → [生成]`。导引单会话内逐字不变，故放在用户文字之前的收益不是"少失效"，而是让 `系统+技能目录+AGENTS+导引单` 成为**跨会话稳定前缀**（新会话首请求即可命中）。旧规假设"导引单会在会话内变化"，该前提已被 R4 的三条纪律消除，故旧规的代价被高估。
