## 1. 背景与目的

需求确定书 §4.3 已实证定位：扫描件路径的现有瓶颈是"OCR 行级坐标被丢弃 + 表格结构修复靠 DeepSeek-V4-Flash-Vision-Exp 通用 VLM 逐表兜底"。试点期间注意到一个关键外部事实：**0.9B–1.2B 量级的专用文档解析模型在 OmniDocBench v1.6 上达 95.15–96.33 综合分、表格 TEDS 最高 94.76，且在扫描、倾斜等真实劣化场景显著优于通用大模型**。

本文目的：系统调研**中文友好**（中文识别质量好、API 界面/文档中文友好）的视觉/文档解析 API，评估其替代或部分替代现有"通用 VLM 逐表兜底"路线的可能性。若对拍测试达标，可能将主方案从"本地管线 + 通用 VLM 兜底"切换为"专用文档解析 API 为主"。

> ⚠️ **路线切换的含义**：主链路若依赖云端 API，则文档内容数据出域成为常态而非例外，与《需求确定书》§10 出域约束相关，须用户另行裁决（见 §7 Q10）。

### 2.2 单表成本估算（L3 逐表兜底口径）

口径：每张可疑表约 440 prompt tokens + 约 3000 completion tokens（试点实测均值），不含缓存命中。

| 候选 | 单表成本（估算） | 相对倍数 |
|------|----------------|---------|
| **C1 GLM-OCR** | **≈ ¥0.0007** | 1×（基准） |
| C2 Qwen3-VL-Flash | ≈ ¥0.0046 | ~7× |
| C4 Qianfan-OCR | ≈ ¥0.0056 | ~8× |
| C6 DeepSeek（空闲时段） | ≈ ¥0.0145 | ~21× |
| C7 豆包 seed-1.6-vision | ≈ ¥0.0244 | ~35× |
| C6 DeepSeek（高峰时段） | ≈ ¥0.028 | ~40× |

> 说明：C3 MinerU 与 C5 PaddleOCR-VL 按页/按次计费，与按 token 口径不可直接比；C5 若 ¥0.09–0.18/页成立，则对"整页解析"场景有竞争力，对"单表裁剪图"场景浪费（按页起计）。

**结论：GLM-OCR 比现默认方案便宜约一个数量级，且是文档解析专用模型。**

## 3. 关键候选详评

### 3.1 C1 GLM-OCR（首选测试对象）

**优势**

- 基准最强：发布时 OmniDocBench v1.5 综合 94.62 登顶，表格、公式分项 SOTA；0.9B 小模型专为文档解析训练。
- 价格极低：输入输出同价 ¥0.2/百万 tokens，官方口径 ¥1 ≈ 2000 张 A4 扫描图或 200 份 10 页 PDF。
- 输入宽容：PDF / JPG / PNG；图 ≤10MB、PDF ≤50MB、≤100 页。
- 吞吐高：PDF 约 1.86 页/秒。
- 智谱平台中文文档与控制台，API 界面中文友好；模型已开源（zai-org/GLM-OCR），未来有本地化退路。

**风险与未知**

- ⚠️ **输出形态不匹配**：GLM-OCR 输出 Markdown 而非《需求确定书》FR-D4 要求的严格 JSON schema（`status/data/rowspan/colspan/confidence/issues`）。**合并单元格在 MD 中如何表达（是否内嵌 HTML table、有无 rowspan/colspan 标注）未经实测**——这是对拍测试的第一优先级验证项。
- 若其 MD 内嵌 HTML 表，需新增一个"MD/HTML → 网格模型"适配层（工作量可控，但属新增组件）。
- 专用模型的输出格式不可自由定制（不同于通用 VLM 可被 prompt 约束出任意 JSON）。

### 3.2 C3 MinerU 官方 API（整页结构化候选）

**优势**

- 输出 Zip 同时含 Markdown 与**结构化 JSON**（版面块、表格结构信息）——可能直接服务 FR-C 整表重建，无需自写适配层。
- vlm 模式基准分高（MinerU2.5-Pro v1.6 ≈95.69–95.75，TEDS 93.62）。
- 能力上限高：单文件 ≤200MB、≤200 页、批量 ≤200；可导出 docx/html/latex。
- 另有免登录 Agent 轻量 API（IP 限频、≤10MB、≤20 页、仅 MD），可零成本先期体验。

**风险与未知**

- ⚠️ 精准解析 API 正式定价未公开，需联系商务；当前仅问卷申请免费试用。
- 异步轮询模式（提交→轮询→下载 Zip），交互链路比同步调用长。
- 整页解析粒度：若只需修复单张表，整页解析的边际成本与时延均偏高。

### 3.3 C2 Qwen3-VL-Flash（严格 schema 遵循候选）

**优势**

- 通用 VLM，可通过 prompt 约束直接输出 FR-D4 严格 JSON schema，**无需适配层**。
- 价格便宜（输入 ¥0.15/M、输出 ¥1.5/M），Batch 再半价；免费 100 万 tokens/90 天足够对拍测试。
- 阿里百炼中文文档完善。

**风险与未知**

- 通用模型在扫描劣化场景的表格结构还原能力，基准上弱于专用文档模型——需实测验证差距是否可接受。
- 与 DeepSeek 同属通用路线，若专用模型实测显著更优，则其价值在于"schema 兼容的低成本平替"。

### 3.4 C6 DeepSeek-V4-Flash-Vision-Exp（已实测基线，留作对照）

- 试点已积累真实表实测数据（900×577 裁剪图，prompt 419–439 tokens、completion ≈2940 字符）。
- ⚠️ 官方"单图 ≤384 tokens"口径与实测矛盾，已列入需求书验证项 V-1；其缓存命中价（¥0.10/¥0.05 每 M）在批量重复结构场景有独特优势。
- 作为对拍测试的**基线对照组**保留，无论是否换主方案都不废弃。

## 4. 对拍测试方案（草案，待 Q10 批准）

**目标**：用同一批真实样本，横向比较候选 API 在我们真实任务上的表现，数据驱动决策是否换主方案。

**样本**：GBJ16-87 第 1 册扫描件中已标记的全部可疑表（试点台账已有清单），另加 2–3 张含跨页表/合并单元格的难例。

**参测组**：C1 GLM-OCR、C2 Qwen3-VL-Flash、C3 MinerU（若拿到试用 token）、C6 DeepSeek（基线）。

**评测维度**（逐表记录，与试点台账同构）：

| 维度 | 度量 | 说明 |
|------|------|------|
| 结构正确性 | 网格守恒校验通过率 + 抽样人工核对 | 行×列展开后单元格数守恒；合并区位置正确 |
| 数值保真 | 单元格文本与原图逐字一致率（抽样） | OCR 错字、丢字、多空格均计错 |
| schema 合规 | 输出能否（直接或经适配层）满足 FR-D4 字段 | C1 需实测其 MD 表格形态 |
| 时延 | 单表端到端秒数 | 含网络与轮询 |
| 单表成本 | 实测 usage × 刊例价 | 台账以实测为准，不采官方口径 |

**通过门槛（建议值，可讨论）**：结构正确性 ≥ DeepSeek 基线且数值保真不劣于基线；单表成本或时延至少一项优于基线 50%。

**前置条件**：需要用户提供或确认各平台 API key（智谱、阿里百炼、MinerU 试用、百度千帆视需要）。

## 5. 推荐排序

1. **C1 GLM-OCR —— 首选测试**。基准最强 + 价格最低一个数量级 + 中文友好 + 有开源退路；唯一大问号是输出形态适配。
2. **C3 MinerU 精准解析 API —— 并行测试**。若其结构化 JSON 直接可用，对 FR-C 整表重建价值最大；先走问卷申请免费试用，定价不明前不做主方案承诺。
3. **C2 Qwen3-VL-Flash —— 低成本 schema 兼容备选**。若专用模型适配成本过高，它是最顺滑的降价平替。
4. **C6 DeepSeek —— 基线对照**。已实测、已入需求书，任何切换都以它为比较锚点。
5. C4/C5/C7/C8：本阶段不投入测试资源，留档备查（C5 定价核实后可再评估）。

## 7. 待裁决事项 Q10

**Q10：是否批准按 §4 方案开展对拍测试？**

- A. 批准：用户提供/确认智谱、阿里百炼（及 MinerU 试用）API key，本代理执行对拍并出具测试报告，再决定是否将《需求确定书》升 v1.1 修订主路线。

> 提示：若测试结论是"全面采用专用 API 为主方案"，则需求书 §10 出域条款、FR-D4 schema（可能改为"MD 适配层产出同构 JSON"）、§5 技术选型表均需相应修订，走需求书变更流程而非直接改代码。
