## 三、轻微（Minor）

### [轻微-1] R-02 triage.json 数据模型与冻结设计 §6.1 不一致：缺 FR-A4 承载字段 `intra_regions`，并多出 `file`/`cjk` 两字段

- **anchor**：`升级-补全v4入口-细化任务书.md` §2 R-02 输入→输出（`work/triage.json`：`{file, page_count, encrypted, locked, degraded:{zero_page, blank_pages[]}, pages:[{page, verdict, ratio, printable, cjk, layout_hint, skew_deg, dpi_ok}]}`）↔ 冻结《详细技术设计.md》§6.1 L326（M1 输出 `work/triage.json`：`{page_count, encrypted, locked, degraded: {zero_page, blank_pages[]}, pages: [{page, verdict, ratio, printable, layout_hint, skew_deg, dpi_ok, intra_regions: [...]}]}`）。
- **basis**：冻结 §6.1 把 M1 职责定义为"分诊 + 版式质量探测 + 退化探测 + **页内区域级探测（FR-A4）**"，其输出 schema 含 `intra_regions:[...]`（FR-A4 检出结果的落盘位）；而对象 R-02 的 triage.json 缺 `intra_regions`，且多了顶层 `file` 与逐页 `cjk`（设计 §6.1 均未列）。对象 §1.2-5 又自称"FR-A4 阈值校准（按初值落地，校准留 MS）"，即 FR-A4 在本次范围内——但对象 M1/triage 数据模型却把 FR-A4 的输出字段删去。影响：R-02 验收"triage.json 字段与 schema 一致（脚本校验）"将按缺 `intra_regions` 的 schema 校验，FR-A4 检出结果可被静默丢弃或无从落盘，与冻结 FR-A4"分流决策留痕 / 有测试"的验收要点脱节。
- **建议处置**：在 R-02 triage.json 增 `intra_regions:[...]`（对齐冻结 §6.1），或把 FR-A4 输出另列 `work/` 文件并**显式声明**与设计 §6.1 的偏离；并澄清 `file`/`cjk` 为有意新增还是误携带（pdf_text_probe.py 每页确有 `cjk`，但设计 §6.1 未列入 M1 输出）。
- **confidence**：中高（设计 §6.1 明列 `intra_regions`、对象缺此字段为高置信；"FR-A4 输出被静默丢弃"的判定为中，取决于实现是否另设落盘）。

### [轻微-2] R-05 验收第 3 条"选 B 路径（若有开关/注入）"用条件式"若有"，削弱可失败性（与 R-07 防假绿灯及简版 R-05 硬口径相悖）

- **anchor**：`升级-补全v4入口-细化任务书.md` §2 R-05 验收第 3 条（"选 B 路径（**若有开关/注入**）→ 才产出 v3.0 且含差异告知"）↔ 同文 §2 R-07（"防假绿灯：每条断言真分母可失败；无空集给 1.0、无短路恒真"）↔ 冻结《简版需求书.md》R-05（"仅当用户选 B 才产出 v3.0（含差异告知）"）。
- **basis**：简版 R-05 硬口径要求"仅当用户选 B 才产出 v3.0（含差异告知）"，是可失败真断言；对象 R-05 行为段亦写"未选择不产出；仅选 B 才允许 v3.0 产物"。但验收第 3 条用"**若有开关/注入**"，"若有"即条件逃生口——若实现未提供"选 B"注入开关（TTY 交互态的真正手动选 B 在自动测试中难以稳定复现，须依赖注入开关），则该验收项空转通过，既未验证"仅选 B 才产出"，也不满足 R-07 的"真分母可失败/无短路恒真"。与对象自己新立的防假绿灯纪律冲突。
- **建议处置**：把第 3 条改为硬断言：规定提供选择注入开关，且"未选/选 A/选 C → 无 v3.0 产物；选 B → 产出 v3.0 且差异告知字段非空"；若实现未提供该注入开关，验收应显式判为"不可测/未通过"，而非"若有"空转。
- **confidence**：高（"若有"确为可空转的条件式，与 R-07 防假绿灯、简版 R-05 硬口径相悖）。

### [轻微-3] R-05 触发条件收尾宽词"使 v4 无法形成产物的情形"与 R-01 数据流"退化输入优雅退出码 3"（冻结设计 §10 TriageError 非弹选）边界未划清

- **anchor**：`升级-补全v4入口-细化任务书.md` §2 R-05 触发条件（"…使 v4 无法形成产物的情形。**不含**：无 key/--no-egress/预算超限/断网（=FR-D7 页/表级自动兜底，不弹窗）"）↔ 同文 §2 R-01 数据流第 2 步（"退化输入（encrypted/locked/zero）优雅退出码 3"）↔ 冻结《详细技术设计.md》§10 L1165（"TriageError(encrypted/locked/zero_page) | M1 | 加密/锁态/零页 | 优雅报错退出码 3，不崩溃（FR-A1）"）。
- **basis**：R-05 把弹选限定为"整管线结构性不可跑"（例举模块缺失/入口断裂/依赖白名单不满足），并以"**不含** 无 key/--no-egress/预算超限/断网"划清与 FR-D7 的边界——这部分忠实承接已闭合的严重-2.1。但触发条件收尾用宽词"**使 v4 无法形成产物的情形**"，可被读为含文档级退化（整册加密/锁态/零页 → v4 同样"无法形成产物"），与对象 R-01 数据流已把 encrypted/locked/zero 钉为"优雅退出码 3"（即冻结 §10 TriageError 路径，**非弹选**）产生边界歧义——"加密/锁态是否触发弹选"未定死。若不划清，实现可能把加密 PDF 误判为"整管线不可跑"而弹选，违背冻结 §10（TriageError→退出码 3）。
- **建议处置**：R-05 触发条件改为"整管线结构性不可跑＝管线自身结构/能力问题（模块缺失、编排入口结构性异常、依赖白名单不满足），**不含**文档级退化输入（encrypted/locked/zero，由 M1 TriageError 优雅退出码 3、不弹选）"，与 R-01 数据流、冻结 §10 统一。
- **confidence**：中（宽词存在歧义读法，但对象 R-01 已钉退出码 3，故判为边界未划清的非严重问题）。

### [轻微-4] R-02 验收"verdict 与 pdf-inspect 现判据一致"未交代 M1 源（pdf_text_probe.py 阈值 0.50/0.30）与 pdf-inspect.ps1 判据是否同源

## 四、建议（Suggestion）

### [建议-1] R-03 "dpi 初值 220"与冻结设计 §3.2"target_width 为指定值、dpi 为派生"的口径未统一说明

- **anchor**：`升级-补全v4入口-细化任务书.md` §2 R-03（"dpi 初值 220，`resolution_steps=[220,180,150]`"）↔ 冻结《详细技术设计.md》§3.2 L115-125（registry 中 `target_width` 优先、`dpi` 为派生值，"dpi = round(pixel[0]/pdf_rect_pt[0]×72)，禁止自相矛盾"）↔ 同设计 §4.2 config（`"render":{"dpi_default":220,...}`）。

- **confidence**：低。

### [建议-2] 非 TTY 检测机制（isatty）与"无法判定 TTY"时的默认行为未交代

- **confidence**：低（实现级，接 Step 4/5）。
