## 1. 已知缺陷处理矩阵（检测信号 → 处理阶梯 → 残余风险）

控制论的基本原理在这里的直接含义：**一个缺陷只有在"可观测"（有检测信号）且"可控"（有纠偏执行器）时才是可管理的**。逐个缺陷按此检验：

### D1 等级类列合并拼接（实测率 9.6%，7/73 表）

- **现象**：纵向合并的标签列（耐火等级、最多允许层数等）格内多值无分隔拼接（"一级二级""不限31"）。
- **检测信号（可观测 ✅）**：签名正则——合并格（rs>1）内出现"汉字紧跟数字"或"级+一/二/三"连写。已实测，误报率可接受（12 命中中约 3–5 为原文即如此）。
- **处理阶梯（可控 ✅）**：
  1. **规则拆分**：规范领域的此类列是**封闭枚举集**（耐火等级∈{一级，二级，三级，四级，一、二级}；层数∈{不限，数字}）。按合并跨度行数与枚举模式做确定性切分，切分结果必须过"行数对齐"校验（rs=3 必须切出 3 份），不过则升级；
  2. **裁剪复核**：取该表块区域（layout_details 给 bbox）裁剪送 Qwen/DeepSeek，prompt 收窄为"只转写第 N 列逐行值"——通用 VLM 在**收窄任务**上可靠（对拍中其文本读取命中 0.95+），将其结果与 GLM 网格做行对齐合并；
  3. **仍不一致 → 标记** `issues:[{defect:"D1", status:"unresolved"}]`，不覆盖、不猜测。
- **残余风险**：低。封闭枚举 + 行数校验使误拆几乎必然被第 1 级自检拦住。

### D2 续表/附录表表头 rowspan 过声明（结构类缺陷的一部分，整册 10/73 表守恒失败）

- **现象**：单行表头被声明 rs=2，首行数据被推入"幻影列"（page_0087 实证）。
- **检测信号（可观测 ✅）**：守恒校验（空洞/越界）+ 特征签名（网格出现近全空列）。必然被抓住——这是守恒门的强项。
- **处理阶梯**：
  1. **幻影列坍缩启发式**：空洞率高的列若仅含表头延伸内容，坍缩重建网格（启发式，结果须再过守恒门）；
  2. **裁剪重译**：按 layout_details 的表块 bbox 裁剪该区域单独送 GLM 重跑——**整页上下文干扰被移除后，第二遍通常显著改善**（试点期 DeepSeek 单表裁剪的成功率高于此种整页模式，GLM 同理可期；此假设列为验证项 V-2）；
  3. 对拍复核 → 4. 标记。
- **残余风险**：中低。续表场景可预期地复发，但每例都被门拦住，不会静默通过。

### D3 无横线子行错位（最危险的一类）

- **现象**：一个序号下多个构造分项各带数值、行间无分隔线，GLM 把数值对到相邻行（page_0087 中序号 6 的分项(6)的 0.45/非燃烧体 被划给序号 7 的首行）。
- **检测信号（部分可观测 ⚠️）**：**守恒校验抓不住它**（错位后网格仍守恒）。可用信号：序号列 rs>1 且其覆盖行内数值列出现多值不一致的模式；与本地 RapidOCR 行文本做"数值-行"对位交叉校验（行级 y 坐标能对上就对位）。
- **处理阶梯**：检测到疑似 → 裁剪该表送第二模型复核（复核 prompt 明确提示"注意无横线子行"）→ 双模型行对位一致才放行 → 否则标记。
- **残余风险**：中。这是智谱模型的真实能力边界（见 §3），也是为什么**本地 OCR 行级坐标通道不能完全退役**——它是 D3 的独立对位信号源。

### D4 占位空 td 怪癖

- 已在适配层解决（空 td 全落入合并覆盖区则丢弃），整册复测验证有效。**关闭。**

### D5 跨页续表拼接

- GLM 逐页独立解析，跨页表的"同一表"语义拼接本来就是 Schema v3 的职责（续表标记已有），现多了"续表"字样与表头重复两个可靠特征。**沿用原设计即可，不属于新风险。**

### 缺陷登记机制（融入 FR-D4）

每张表的 JSON 增加 `issues[]` 元素：`{defect_class: D1|D2|D3, detected_by: conservation|signature|cross-check, resolution: rule-split|crop-retry|second-opinion|marked, status: resolved|unresolved}`。全册产出一份缺陷台账（页码→缺陷→处理结果），这正是对抗审查与人工抽检的入口。

## 2. 第一性原理推演：整册可解析时代，"分流 JSON 化"还有用吗

### 2.1 回到信息本质

一份扫描规范页包含的信息原子：**字符内容、阅读顺序、层级结构（章/节/条/注）、表格网格语义、图件像素、以及一切内容的版面坐标（可溯源性）**。原"分流"设计的隐含假设是：*这些信息必须按载体类型（文字/表格/图片）分别用专用本地工具提取，再组装*——这是在"本地 OCR 只能给词行、无法理解结构"的约束下的合理工程解。

### 2.2 整册实测改变了什么

180 页批跑给出了 GLM 整页解析的实际交付清单：

| 信息原子 | GLM 实测交付 | 证据 |
|---|---|---|
| 字符内容 | 高质量全文（条文说明页抽查：文字、标点、上下标均优） | page_0110 等抽查 |
| 阅读顺序 | 按版式正确排序的 Markdown | 同上 |
| 表格网格语义 | HTML 表（rowspan/colspan），86% 直接守恒 | §7 批测 |
| 版面块坐标 | 每块 bbox_2d + 类型（text 1161 / paragraph_title 98 / figure_title 113 / table 84 / **image 5** / display_formula 4 / vision_footnote 50） | 标签分布统计 |
| 章/节标题层级 | 部分以 `#` 标题输出（14 页有章/节标题） | 标题统计 |
| 公式 | LaTeX（如 `$300\times300\mathrm{mm}$`） | page_0110 |
| 图件 | image 块给 bbox（content 为空）→ **可从渲染页裁剪成附件图片** | page_0142/0143/0173 |
| 条文号结构（第 x.y.z 条） | 保留在文本流中但**不标层级** | 需后处理 |
| 字号几何 | 无（块级 bbox 高度可粗略估计，不如行级精确） | — |

### 2.3 结论：分流没有消失，而是改变了角色

**前馈式分流（旧）**：先按载体拆分页面区域，再分别用本地工具处理，再组装。
**反馈式单通道+校验（新）**：整页一次解析 → 校验门检测 → 仅对检出的缺陷点做局部再处理。

原分流中的各组件并未报废，而是角色转换：

- **本地 OCR（RapidOCR）**：从"主生产者"转为**独立校验信号**（D3 行对位、数值交叉核对）。它的错误与 GLM 的错误不相关，这正是冗余通道的价值——控制论中的"多样性冗余"原则。
- **表格检测/裁剪**：从"先检测再识别"转为"按 layout_details 块坐标直接裁剪"——更准确且零检测成本。
- **pdfplumber 文本层路径**：**完全保留**。第一性原理：文字版 PDF 的字符与坐标是**确定性地存在文件里的**，本地提取是零误差、零成本、零出域的直达路径；让视觉模型去读文字版截图反而是引入噪声的迂回。分诊（文字层 vs 扫描）作为第一级路由不变。
- **章节条文拆分器**：GLM 不标条文层级，这套正则/逻辑**不仅保留，且输入质量大幅改善**——从噪声 OCR 文本换成干净的有序文本，拆分准确率只会提高。
- **图件附件化**：从"图像检测"变为"按 image 块 bbox 裁剪"，更简单可靠。

**一句话：不是"分流还有没有用了"，而是分流的产出者从 N 个本地专用工具收敛为 1 个云端整页解析器，本地工具集体转任校验员与兜底员。** 这符合控制论的结构原则：执行通道可以单一，**观测与纠偏通道必须冗余且独立**。

## 3. 智谱专用模型的能力边界（基于实测的能力地图）

| 能力带 | 实测表现 | 处置策略 |
|---|---|---|
| **可靠区**：单/多级表头、斜线表头、合并单元格（数值区）、全文 OCR、阅读顺序、版面块定位、图件定位、公式→LaTeX | 难例 4/4、整册零漏检、块标签体系完整 | 直接采信，过守恒门即可 |
| **风险区**：纵向合并标签列多值（拼接）、续表/附录表表头（rowspan 过声明）、超长无横线表（子行错位） | 9.6% / 部分含在 13.7% 结构问题中 / D3 个例 | 校验门必拦 + 阶梯处理（§1） |
| **盲区**：条文层级语义（第 x.y.z 条不标层级）、字号几何、单元格级坐标、跨页表的同一性语义 | 实测确认 | 本地后处理补齐，不指望模型 |
| **未验证区**：手写、印章（规范场景无关）；并发限流；第 2/3 册页型一致性 | — | L-7 跟踪，非阻塞 |

边界形态判断：风险区缺陷**全部是"结构映射"层面的，而非"字符识别"层面的**——模型看得清字，偶尔摆错格。这决定了纠偏成本很低（重译/拆分的是结构，不是重新认字），也决定了第二意见通道用通用 VLM 足够（它们的短板恰是 GLM 的长板，反之亦然——**误差独立性成立**）。

## 4. 融入需求设计（v1.1 修订清单）

若 Q11=A，需求书按以下要点修订（v1.0 存档，走变更流程+对抗审查）：

1. **主链路（扫描路径）重写为**：
   `分诊 → [文字层: 本地确定性提取] / [扫描: GLM-OCR 整页] → 适配层(HTML表→网格JSON, D4规则, 幻影列坍缩) → 校验门(守恒/签名/交叉对位) → 缺陷阶梯(规则修复→裁剪重译→第二意见→标记) → 章节条文结构化(本地正则) → 图件按块裁剪附件化 → v3 JSON`
2. **FR-B1 修订**：扫描路径坐标来源 = GLM 块级 bbox（主体）+ 本地 OCR 行级（校验与 D3 对位，可选增强）；文字层路径不变。
3. **FR-D4 扩展**：表格 JSON 的 `issues[]` 增加缺陷登记结构（§1 末）；schema 本体不变，适配层为新增组件。
4. **新增 FR-E（缺陷闭环）**：校验门三信号（守恒/签名/交叉对位）+ 四级处理阶梯 + 缺陷台账产出。
5. **§5 技术选型表**：GLM-OCR 升为主解析器（扫描件）；DeepSeek 降为第二意见/兜底；Qwen3-VL-Flash 标注"结构场景不推荐，文本复核可用"；RapidOCR 转为校验通道；MinerU/PaddleOCR-VL 留档。
6. **§10 出域条款**：扫描件整页出域常态化——需明确：涉密/敏感文档的开关（强制本地路径）、出域前的用户提示、API 供应商变更的替换策略。
7. **验收标准量化**（新增可测条款）：整册级——成功率 ≥99%、表格零漏检、结构守恒直通率 ≥85%、缺陷台账捕捉率 100%（不允许静默通过）、单册成本 ≤¥0.5。
8. **验证项更新**：V-1（DeepSeek 口径）保留；新增 V-2（裁剪重译对 D2 的修复率）、V-3（第 2/3 册各抽 20 页一致性）。

## 5. 对 Q11 的最终意见

补测后的证据链完整：**整册可用性（100% 成功、¥0.16、13 分钟）、零漏检、缺陷有界且全部可观测、纠偏阶梯每一级都有实测支撑、本地组件各有新角色**。残余风险集中在 D3（无横线子行错位），已由"交叉对位 + 第二意见 + 不覆盖原则"三重控制覆盖。

**建议选 A（批准切换）**，并按 §4 清单修订需求书 v1.1。若您对 D3 的残余风险仍不放心，可选 A 的变体：v1.1 中把"交叉对位通道（本地 OCR 行级保留）"从"可选增强"升为"默认开启"——成本是每册多跑一遍本地 OCR（免费、约几分钟），换来 D3 类缺陷的独立观测信号。
