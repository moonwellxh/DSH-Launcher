### 轻微-1　R-09 实现与断言互相矛盾：单次调用 dpi_floor 模型 vs 两段式 side_effect 测试模型

- **anchor**：设计 §2 R-09 产品第 1 步（L115 "reg = render_page(…, dpi_floor=96)（floor 常量…）→ registry 追加 → OCR"）与 L114（"以 floor 为最低 dpi **再试一次**"，floor 为 render_page 内部机制）；对照同节断言（L119 "`render_page` side_effect=[RenderError oversize, floor-reg]→**二次调用**断言 dpi_floor 生效 + …OCR 产出文本非空"）及 §1 表 R-09 行（L43 "先抛 oversize→floor 二次重渲…"）。
- **basis**：两种实现形态互斥。若按 L115 的单调用模型（floor 随首次调用传入、render_page 内部兜底），则 orchestrator 层对 render_page 只会调用一次；L119 的 side_effect 第二段（floor-reg）永不消费——mock 首段即抛 oversize，_scan_page_local 直接进 except 分支产出诚实 part，L119 的 "最终 png ≤10MB + OCR 产出文本非空" 断言在该场景下必失败。若按 L119 的两段式模型（先无 floor 抛 oversize、再带 floor 重调），则 L115-116 "render_page(…, dpi_floor=96) 单次调用" 的描述即错，且与 render_page 内部兜底的机制（L114）重复。任务书 R-09 验收的表述（"构造需降到 floor 才 ≤10MB 的页 → 断言最终 png ≤10MB 且 OCR 有产出"，V-5）更接近渲染级单调用形态。Step 5/6 须择一并把断言与实现同构：单调用→断言捕获单次调用 kwargs 含 dpi_floor=96（或 render 级直接测 floor 候选成功/仍超两分支）；双调用→明确两段流程并把第一段"无 floor 尝试"写进产品实现。

## 四、建议级

### 建议-1　R-02 夹具可制造性依赖人工试错：竖线密铺图的 PNG 压缩特性未纳入夹具设计

- **anchor**：设计 §2 R-02（L65-67 夹具有效性前置"按 dpi_default 取 pixmap 存临时 png → 断言 >10MB（不足则调 step/dpi 校准）"）；诚实声明（L208）。
- **basis**：竖线密铺（line step 2pt）使每条扫描线内容高度相似，PNG 行滤波后差分≈0，压缩率极高——2000×2800 现行夹具即因此从未在 220dpi 触发 >10MB（遗留 C-2 佐证其"弱"），单纯放大到 ≥5000pt 不保证 >10MB；反之若加噪声至必 >10MB，又可能在 150dpi 仍 >10MB 使 render 抛 oversize，R-02 无法绿。诚实声明已覆盖"经验初值需校准"，非缺陷，但"校准"将落在 Step 7 靠前置断言试错。建议 helper `make_dense_pdf` 显式参数化（w/h/step + 灰阶噪声横线破坏行相似性）并给出"前置失败→调参方向"指引（密度↑ 或 加噪声；降档侧由 resolution_steps 兜底）。
- **confidence**：medium（PNG 压缩行为为原理推断，未实测 ≥5000pt 夹具文件大小）。
- **影响**：仅影响 Step 7 落地节奏；不改判据语义。

### 建议-2　R-07 登记口径未钉"缺省路径 dpi 记档值、target_width 路径记派生值"，存在 R-02 单判据/m-05 语义漂移风险

- **anchor**：设计 §2 R-07（L103 "dpi=round(实际宽×72/pdf_w,4)（m-05 两向保持）"）；§1 表 R-02 行（L36/L67 "reg.dpi<dpi_default 单判据"）。
- **basis**：若缺省路径（无 target_width）成功候选也按"实际宽→派生 dpi"登记，A4 页（pdf_w=595.0pt）220dpi 成功时 tw=round(595×220/72)=1818 → dpi=round(1818×72/595,4)≈219.99 ≠ 220.0：registry dpi 语义从"档位值"变"派生值"（cache 指纹含 render.dpi → 升级后缓存一次性失效可接受；px_to_pt 用 scale 不受影响）。R-02 断言因夹具有效性前置（默认档必 >10MB）不会假绿，但 R-07 设计文字未区分"缺省成功路径记 220.0 / target_width 指定路径记派生值"，若照抄 L103 统一派生会让 registry dpi 普遍 < dpi_default，令 R-02 的"dpi 单判据"未来失去区分力。建议 R-07 明确：缺省路径成功候选登记 dpi=候选档位原值（220/180/150），仅 target_width 指定路径登记派生 dpi。
- **confidence**：medium（派生漂移为数值推演；登记语义是否真变取决于 Step 5 具体实现）。
- **影响**：Step 7 实现歧义 + registry 语义漂移的预防性钉死。

### 建议-3　R-13 回归断言定位句"防 GLM 升级漂移"高估离线夹具断言能力

- **anchor**：设计 §1 表 R-13 行（L47 "180 夹具逐页 count==、逐位序一致回归；…防 GLM 升级漂移"）；§2 R-13 断言 1（L155 "180 页循环加：…（同预研公式，防 GLM 升级漂移）"）。
- **basis**：test_ms2_replay（实物）为黄金夹具离线重放、零网络（文件头 L3-13 明示不打 API；L45-53 从冻结 page_*.json 读数据），回归断言重算的是**冻结数据**上的 count/序一致性——只能防适配层/pipeline 回归与"夹具重新录制后"的新数据漂移，本身无法拦截真实 GLM 升级（夹具不变时断言结果恒定）。建议措辞改为"防夹具重录/适配层回归致序错位"或注明"GLM 升级漂移仅在夹具重新录制时被本回归覆盖"。
- **confidence**：high（test_ms2_replay 离线性质直读 + 断言输入为冻结 fixture）。
- **影响**：文档表述准确性；不改变断言本身价值（防 adapter 回归仍成立且可失败）。

### 建议-4　R-09 断言未校验 marker 落盘的 reason 字段（V-5 语义"原因入页"的收口断言缺位）

- **anchor**：设计 §2 R-09（L117 "…+ `_marker(…, reason='render_oversize')`"；L119 断言仅 "part routing note 含 render_oversize"）；对照任务书 R-09 验收（"诚实标记 page part 含 reason='render_oversize'"）与需求书 R-09（"诚实标记且原因入页 part（reason=render_oversize）"）。
- **basis**：任务书/需求书把验收语义钉在 part/marker 的 reason 上；设计产品部分写明了 marker reason，但 L119 断言只检查 part.routing.note 文本包含 "render_oversize" 子串——note 含词不等于结构上有 reason 字段，若实现把 reason 写错键位（如 note 之外漏写 marker reason），该断言仍绿。建议补断言：恒抛 oversize 场景下 `out/work/marks/page_%04d.json` 的 `reason == "render_oversize"`（若语义定位 marker）或 part 携带离散 reason 键。
- **confidence**：medium（V-5 语义落点的权威表述为 reason=render_oversize；note 子串判定与字段判定确有差距）。
- **影响**：断言覆盖缺口，防"仅标记即过"的守卫多一层保障。
