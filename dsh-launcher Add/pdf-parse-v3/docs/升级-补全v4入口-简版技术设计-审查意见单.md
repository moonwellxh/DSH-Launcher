## 二、严重（Severe）

### [严重-1] M1 triage 复用 `pdf_text_probe.verdict`，其取值域与 M12 `route_page` 分支词表互不匹配，核心路由未闭环

- **anchor**：`升级-补全v4入口-简版技术设计.md` §2 模块表 M1 行（"verdict 阈值 0.50/0.30 沿用"、职责列 "text/scanned/hybrid/退化/页内区域探测"）↔ 同文 §3.1（triage 注释 "复用 pdf_text_probe：…verdict(0.50/0.30)"、返回体 `pages:[{page,verdict,…}]`）↔ 同文 §3.3 route_page（"text→textlayer_page；scanned→render→glm(+ocr)；hybrid 逐页；unknown→scanned"）。
- **basis**：实物 `assets\pdf_text_probe.py` 的 `verdict(st)`（L63-72）返回域 = **{text, image, pseudo}**（raw==0→image；ratio<PSEUDO_MIN_RATIO→pseudo；printable≥5 且 ratio≥TEXT_MIN_RATIO 0.50→text；否则 image），**不产出 scanned / hybrid / unknown 中任何一个**；而冻结 FR-A1（需求确定书 L117）与 SKILL.md §1（pdf-inspect.ps1 "verdict: text | scanned | hybrid"）用的是 **{text, scanned, hybrid}** 词表。设计 §3.1 让 triage 直接复用该 `verdict`，但 §3.3 route_page 的分支键却是 {text, scanned, hybrid, unknown}。因 triage_rec["verdict"] 仅供 route_page 分支，若原样透传，route_page 的 scanned/hybrid/unknown 分支对其余页（image/pseudo）**无匹配入口**（既不落入 scanned，也无 hybrid/unknown）；若实现侧自行映射，则设计**未给出** image/pseudo→scanned 与 hybrid（文字层页含栅格表/图区）的派生规则，属定义缺口。该缺口直接决定逐页路由，影响 R-01/R-04 的"逐页路由、每页 routing 留痕"验收与 FR-A1 分流，属接口级而非字段级问题。
- **建议处置**：在 §3.1 明确 triage.verdict 的取值域与 route_page 分支一一对应的映射（如顶层 `verdict ∈ {text,scanned,hybrid,unknown}`，image/pseudo 归 scanned，text 层且 intra_regions 非空归 hybrid，探测失败归 unknown→scanned）；或在 §3.3 把 route_page 分支键改为与 `pdf_text_probe.verdict` 一致（{text,image,pseudo}）并保留 hybrid 判定来自 intra_regions。二选一并全篇统一，避免 Step 5 按两套词表实现错位。
- **confidence**：高

### [严重-2] §3.2 的 `build_registry_entry` 把 dpi/target_width 指定/派生关系说反，且与冻结 §3.2 m-05 口径相悖、内部自相矛盾

- **anchor**：`升级-补全v4入口-简版技术设计.md` §3.2（`build_registry_entry(page, png, pdf_rect_pt, target_width, dpi)`；"dpi 与 target_width：**dpi 为指定值、target_width 为派生**（对齐冻结 §3.2 m-05 口径，dpi=round(pixel_w/pdf_w_pt×72)）"）；§3.2 render_page（"dpi 初值 cfg.render.dpi_default(220)"）↔ 冻结《详细技术设计.md》§3.2 L117-118（`"target_width": 1860, // 渲染目标宽 px（指定值，优先于 dpi）`；`"dpi": 225, // 派生值 = target_width/pdf_rect_pt[0]×72`）↔ 同设计 L125（m-05："`dpi` 与 `target_width` 二选一为**指定值**、另一为**派生值**，…必须满足 `dpi = round(pixel[0]/pdf_rect_pt[0]×72)`，禁止自相矛盾"）。
- **basis**：① 冻结 §3.2 的**示例**（L117-118）以 `target_width` 为指定值（"优先于 dpi"）、`dpi` 为派生值，派生公式正是 `dpi = round(pixel/pdf_rect_pt×72)`；而设计 §3.2 断言"**dpi 为指定值、target_width 为派生**"，方向与冻结示例相反，却仍标注"对齐冻结 §3.2 m-05 口径"——属**误标**（m-05 仅约定"二选一指定、另一派生 + 一致性公式"，并不指定 dpi 或 target_width 哪个是指定值；冻结示例明确 target_width 优先）。② 设计该注释同时给出派生公式 `dpi=round(pixel_w/pdf_w_pt×72)`（该公式是"dpi 为派生"时用），却又断言"dpi 为指定值"——公式与断言**互斥**，自相矛盾。③ `build_registry_entry(page, png, pdf_rect_pt, target_width, dpi)` 把 target_width 与 dpi **同时作为入参**，与 m-05"二选一为指定、另一为派生"互斥（若 target_width 为派生，则不应作为输入）。④ 实物 `config.default.json` §render 仅含 `dpi_default:220`、`resolution_steps:[220,180,150]`，**无 target_width**——设计"dpi 为指定值"与实际 config 同向（故操作路径可行），但"对齐冻结 §3.2 m-05（target_width 优先）"的表述与实际 config、冻结示例两向都不符。该口径决定登记 `dpi/pixel/scale`，是 FR-B2"给定 bbox 可复算裁剪区"与 R7 风险（坐标系不一致→裁错区）的根基，设计级明确偏差。
- **建议处置**：§3.2 改为与冻结 §3.2 示例一致（target_width 为指定值、dpi 为派生，`dpi=round(pixel/pdf_rect_pt×72)`），或若坚持 dpi 为指定值，须显式声明这是对冻结 §3.2 方向的**有意偏离**并给出 target_width 的派生式（=pixel[0]）与 config 依据；同时把 `build_registry_entry` 的入参改为只收"指定值"一方（dpi 或 target_width），另一方由内部派生并写入登记。
- **confidence**：高
