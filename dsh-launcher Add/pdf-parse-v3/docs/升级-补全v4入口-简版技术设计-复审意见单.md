## 二、严重（Severe）

### [严重-1] §3.5 复用 `pipeline.process_page_md` 的 `raw_resp` 输入契约未钉定，与 `process_page_md` 实际期望不符（字面执行会静默丢失图片索引）

- **anchor**：`升级-补全v4入口-简版技术设计.md` §3.5 项1（"`VisionClient.glm_parse_page(png, page, doc_sha1, render_reg)` 得 md_results/**raw_response** → `pipeline.process_page_md(page_no, md, cfg, ocr_lines=…, ocr_available=…, m4=client, raw_resp=…)` 产出 page part（含 tables/images）"）↔ 实物 `assets\v4\vision_client.py` `_result_of`（L508-515，`"raw_response": raw`；`raw` 为 `_glm_live`/`_finalize_miss` 的外层包装 `{http_status,latency_s,response,usage_extracted}`）↔ 实物 `assets\v4\pipeline.py` `process_page_md`（L53-89）与其 `_image_blocks`（L34-50，`(raw_resp or {}).get("layout_details")`）↔ 实物同文件 `run_fixture`（L116-118，`raw.get("response")` 作为 `raw_resp`）。
- **basis**：① `glm_parse_page` 返回值 `res` 中 `md = _md_of(…) = resp.get("md_results")`（vision_client L607-618），而 `raw_response = raw`（L512）即外层包装 `{"http_status","latency_s","response":<GLM JSON>,"usage_extracted"}`——**该包装不含 `layout_details`**（`md_results/layout_details/data_info` 均嵌在 `raw["response"]` 内，见 L316-343、L586-605）。② `process_page_md` 的 `raw_resp` 唯一消费点是 `_image_blocks(raw_resp)`，其做 `(raw_resp or {}).get("layout_details")`（pipeline L37）；若按字面 `raw_resp = res["raw_response"]`（外层包装），`.get("layout_details")` 恒为 None → `_image_blocks` 恒返 `[]` → page part 的 `images` 恒空，真 `<pdf>` 路径下的图片/图文件索引（FR-B6/S6，也是 M10 figures 的 `_image_blocks` 源）**静默丢失**。③ `run_fixture` 之所以正确，是因为它读夹具 `page_NNNN.json`（= orchestrator 落的 `res["raw_response"]`）后传的是 `raw.get("response")`（pipeline L116-118）——即**正确值应为 `res["raw_response"]["response"]`（GLM JSON，含 `layout_details`）**，而非外层包装 `res["raw_response"]`。④ 设计用词"得 md_results/**raw_response** → raw_resp=…"把代码里的外层包装名"raw_response"与 `process_page_md` 的 `raw_resp` 参数直接对应，属术语碰撞：`md`(=md_results) 传对了，但 `raw_resp` 若照字面传 `raw_response` 则与 `run_fixture` 契约不一致。这是 S-3 所声称的"复用（产出含 tables/images）"与 `process_page_md` 实际输入契约之间的真实断点，属接口级而非字段级。
- **建议处置**：§3.5 项1 明确钉定：`md = res["md"]`（或 `res["raw_response"]["response"]["md_results"]`）、`raw_resp = res["raw_response"]["response"]`（含 `layout_details` 的 GLM JSON）；并注写"不可把 `raw_response` 外层包装直接传入 `raw_resp`（否则 FR-B6/S6 图片索引恒空）"。作者本意若是 GLM JSON，则把措辞从"raw_response"改为"response payload（即 res['raw_response']['response']）"，消除术语碰撞。
- **confidence**：中

## 三、轻微（Minor）

### [轻微-1] §3.1 路由词表含 hybrid/skip_degraded，但页级映射仅由 verdict 推导出 {text,scanned}；hybrid 页级来源与 §2 M1 词表不一致

- **anchor**：`升级-补全v4入口-简版技术设计.md` §3.1（"路由词表（route_page 分支）：text | scanned | hybrid | unknown | skip_degraded"，映射表 text→text / image→scanned / pseudo→scanned / unknown→scanned）↔ 同文 §3.3 route_page（"…hybrid 逐页（§3.1 映射）"）↔ 同文 §2 M1 行（"text/scanned/hybrid/退化/页内区域探测；verdict 阈值 0.50/0.30 沿用"）。
- **basis**：① 映射表只从页级 verdict {text,image,pseudo,unknown} 产出 {text,scanned}；hybrid 只在文档级定义（§3.1"hybrid=同册既有 text 又有 image/pseudo 页"），未给出**页级 hybrid 的推导**（如 text 页且 intra_regions 非空 → hybrid/重路由）。但 §3.3 route_page 仍列"hybrid 逐页"分支；若按"每页路由为 hybrid"读，与 §3.1 的"hybrid 仅文档级"冲突；若意为"混合文档逐页按各自 verdict 路由"，宜在 §3.1/§3.3 统一措辞。② §2 M1 行用 text/scanned/hybrid 作页类词汇，与 §3.1 明确的页级 verdict 值域 {text,image,pseudo} 不一致（scanned/hybrid 是路由输出词，非 verdict 值）。属词表/术语未全篇统一，是上轮 S-1 词汇错位的余绪（范围小，非取值遗漏，故未升级为严重）。
- **confidence**：中

### [轻微-2] `unknown` 映射分支实际无来源；`skip_degraded` 未连到 triage 的 `degraded` 输出

- **anchor**：`升级-补全v4入口-简版技术设计.md` §3.1（"unknown→scanned（探测失败，保守路由）"、"路由词表 …skip_degraded"）↔ 实物 `assets\pdf_text_probe.py` `verdict()`（L63-72，仅返回 {text,image,pseudo}）↔ 同文 §3.1 triage 返回体 `degraded:{zero_page,blank_pages[]}`。
- **basis**：① 复用的 `verdict()` 从不返回 unknown（raw==0→image；ratio<PSEUDO_MIN_RATIO→pseudo；printable≥5 且 ratio≥0.50→text；否则 image），故"unknown→scanned"是防御性死词表——除非 M1 triage 在探测异常时自行合成 unknown。② skip_degraded 作为路由词表值，未声明其由 triage 的 `degraded{zero_page,blank_pages}` 触发，zero/blank 页路由去向未明确。属防御性/未尽连的定义缺口（不阻断取值闭环，但会影响 Step 7 对"退化页走何路径"的一致实现）。
- **confidence**：中

### [轻微-3] §2 模块处置表仍漏 M14 geo_rebuild（上轮轻微-4，未闭合、未升级）

- **anchor**：`升级-补全v4入口-简版技术设计.md` §2 模块表（列 M1/M2/M12/M13/M3/M4..M11，无 M14）↔ SKILL.md §0.1 模块清单（含 geo_rebuild M14）↔ 冻结《详细技术设计.md》§6.14/§7.5。

## 四、建议（Suggestion）

### [建议-1] §3.2 在 dpi 驱动（config 无 target_width）下把反推的 target_width 标为"指定值"，与实际因果方向相反

- **anchor**：`升级-补全v4入口-简版技术设计.md` §3.2（"config.render 现仅含 dpi_default=220（无 target_width）…渲染按 dpi 档位驱动（resolution_steps）…以目标 dpi 反推 target_width 作为登记指定值"）↔ 冻结《详细技术设计.md》§3.2 L117-118、m-05（target_width 指定、dpi 派生）。
- **basis**：m-05 只要求"二选一指定、另一派生 + 必满足 `dpi=round(pixel/pdf_rect_pt×72)`"，登记层面满足该式、无两值互斥（S-2 主问题闭合）。但在 config 现状下，实际驱动程序的是 dpi（dpi_default/resolution_steps），target_width 是反推结果；登记把 target_width 标为"指定值"与事实因果相反。不影响坐标链（该式在 ±1px 取整误差内成立，无系统性偏差），建议加一句"登记按 m-05 约定统一标 target_width 为指定值"，避免读者/实现者误以为 target_width 为用户实设、dpi 可自由写。
- **confidence**：低-中

### [建议-2] §3.5 文字层页"含 reroute 信号"与 §3.3 route_page 分支未连

- **anchor**：`升级-补全v4入口-简版技术设计.md` §3.5 项2（"`textlayer.textlayer_page(pdf, page_no, render_reg, cfg)`…产出即 page part，含 reroute 信号"）↔ 同文 §3.3 route_page（"text→textlayer_page"）。
- **basis**：设计让 textlayer_page 对 text 页产出 reroute 信号，暗示"text 页含栅格表/图区（intra_regions 非空）时经 reroute 转扫描路径"（FR-A4）；但 §3.3 route_page 分支表只写 text→textlayer_page，未明示该 reroute 的触发与接续（text 页何时、以何信号转 scanned）。建议 §3.3/§3.5 补一句"text 页且 textlayer 输出 reroute 信号 → 转 scanned 路径（渲染→GLM+OCR）"，把 FR-A4 区域补测的接续说清。
- **confidence**：中

## 五、收敛小结（S-1 / S-2 / S-3 闭合判定）

**S-1 — 闭合**：§3.1 页级 verdict 值域 {text,image,pseudo} 与 `pdf_text_probe.verdict()` 实际返回一致（L63-72）；映射 text→text、image→scanned、pseudo→scanned（FR-A2）、unknown→scanned（保守），取值无遗漏；文档级 hybrid（同册 text+image/pseudo）已交代，且页级 unknown 不阻止文档级 hybrid 判定。残留为词表/术语未全篇统一（轻微-1/2），不阻断取值闭环。

**S-2 — 闭合**：§3.2 已翻转为 target_width 指定、dpi 派生，登记恒满足 `dpi=round(pixel_w/pdf_rect_pt_w×72)`，与冻结 §3.2 m-05（L117-118）一致；`build_registry_entry(page,png,pdf_rect_pt,target_width)` 签名已删 dpi（消除两参数互斥）；config 现状（仅 `dpi_default=220`，无 target_width，实物 config.default.json L35-38）下按 dpi 档位渲染、反推 target_width 为登记指定值，自洽且无误导坐标链。仅剩"指定值"标签与因果方向的表述细节（建议-1）。

**S-3 — 基本闭合，但引入 1 条新严重（严重-1）**：复用 `pipeline.process_page_md`/`assemble_v4`、M5 调用点（`ocr_pages(png_dir,cfg,out_json)` / `ocr_page(png,engine,page)` + `_load_ocr_lines` → `{page:lines}`）、M4 降级（`Ladder.resolve`/`resolve_hint` 内 catch `VisionError` 并 `_marked`，不弹窗，与"诚实标记"符合）、文字层复用 `textlayer.textlayer_page`、离线验收（`acceptance_offline`/`tests/v4` 四件）路径不变——均与实物签名/行为一致；**唯一断点**在 §3.5 项1 把 `raw_resp` 与 `raw_response`（外层包装）术语碰撞，字面传参会致图片索引恒空（违反 FR-B6/S6）。

**是否发现新阻断/新严重**：新阻断 0；**新严重 1 条**（严重-1）。上轮轻微/建议未升级为严重；上轮轻微-4（M14 漏列）仍为轻微（轻微-3，未闭合，如实记录）。

**是否可放行**：按判据（阻断清零∧严重清零）→ 当前仍存在 1 条新严重，**暂不可放行**。待 §3.5 项1 钉定 `raw_resp = res["raw_response"]["response"]`（或改述为 GLM response payload）、消除术语碰撞，并顺带收敛轻微-1/2、建议-1/2 后即可放行进入 Step 5。复者判断：S-1/S-2 无回归、判定闭合，仅需封堵 §3.5 的 `raw_resp` 契约缺口。
