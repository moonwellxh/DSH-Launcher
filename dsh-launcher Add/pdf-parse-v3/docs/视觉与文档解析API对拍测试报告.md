## 1. 结论（先说结论）

**GLM-OCR 全面胜出，建议作为主方案：** 在 4 页真实扫描表格难例上，GLM-OCR 结构正确性 **4/4 全过**（含斜线表头、三级嵌套表头），Qwen3-VL-Flash **0/4 全败**（网格重叠/越界/不守恒）；同时 GLM-OCR 单页成本约为 Qwen 的 **1/5**、时延约为 **1/6**。文本识别质量两者相当（词元命中率均在 0.83–0.98，差异在参照 OCR 质量噪声范围内）。

对拍前调研阶段标记的最大不确定项 **U-1（GLM-OCR 合并单元格输出形态）已闭环**：实测其输出 Markdown 内嵌 **标准 HTML `<table>`，rowspan/colspan 标注准确**，经简单解析即可还原为满足守恒约束的网格模型，适配层工作量证实可控（本报告的评测脚本已包含该适配器原型，约 40 行）。

- **参测**：智谱 GLM-OCR（`layout_parsing` 端点，图片 data URI 直传）；阿里百炼 Qwen3-VL-Flash（OpenAI 兼容端点，严格 JSON schema prompt，temperature=0，max_tokens=12000）。
- **维度与口径**：结构守恒（sum(rs×cs)=行×列、无重叠无越界，全自动）；文本保真代理（单元格文本去空白后在本页 RapidOCR 参照文本中的命中率，整格/词元/纯数值格三口径）；schema 合规；时延；成本（实测 usage × 刊例价）。

## 4. 人工逐格核验（关键样本）

- **page_0010（最难：斜线表头）GLM 输出与原图逐格比对 = 全部正确**。斜线表头被正确坍缩为跨 2 列的单格；墙（rowspan=4）、柱（rowspan=2）合并位置准确；"非燃烧体 4.00"双行格完整；全部 44 个数值格逐一核对无误。
- **page_0046（三级表头）GLM 输出 = 全部正确**：`名称` rowspan=4、两组 `colspan=3` 的耐火等级分组、"—"空值位置全部正确。
- **page_0013 GLM 存在一类语义压缩缺陷**：`耐火等级` 列与 `最多允许层数` 列被按生产类别纵向合并，格内多行文本**无分隔直接拼接**（"一级二级"、"不限31"=不限/3/1）。数值矩阵区（占地面积各列）仍逐行正确。该缺陷**不影响数值数据区**，但表头侧的等级↔行对应关系需后处理恢复（可结合行序推断或 `layout_details` 坐标切分）。
- **Qwen 失败模式一致**：文字读取好（page_0010 数值格命中 1.0），但网格几何纪律差——斜线表头尝试建 2 行表头时坐标重叠级联；page_0046 把 7 列真实结构臆造为 9 列。通用 VLM 用 prompt 强约束也守不住复杂表的网格守恒，**与试点期 DeepSeek 的观察一致**。

## 5. 附带发现（超出测试目标的价值）

GLM-OCR 响应除 `md_results` 外还含 **`layout_details`：每个版面块的 `bbox_2d` 坐标 + 内容 + 块类型**（text/figure_title/table 等），并附页面宽高。这意味着：

1. 表格外文字区同样有坐标——可服务需求书 FR-B1（坐标入 JSON）的扫描路径，**无需本地 OCR 行框保留机制也能拿到块级坐标**（行级精度待验证）；
2. 表格块自带 bbox——可反向用于"先整页解析、再按块裁剪复核"的闭环，替代试点方案中的红线检测定位。

## 7. 整册补测（2026-09-06，Q11=B 增补）

**设置**：GBJ16-87 第 1 册**全部 180 页**串行批跑 GLM-OCR（断点续跑机制），适配层增加"占位空 td 自动丢弃"规则后评测。

### 8.1 全册运行指标

| 指标 | 数值 |
|---|---|
| 成功率 | **180/180（100%）** |
| 整册总成本 | **¥0.1615**（输入 687,120 + 输出 120,353 tokens） |
| 单页时延 | 均值 4.25s / 中位 2.47s / p95 9.14s / 最大 104.77s（个别页排队） |
| 整册串行总耗时 | ≈13 分钟 |

→ **成本与速度完全满足"整册常态化解析"**：一册规范不到 2 毛钱、一刻钟跑完。

### 8.2 表格检测与结构正确性

- 共检出 **73 张表**（73 页）；OCR 文本含"表N"但 GLM 未检表的 25 页**逐类抽查后确认全部是条文说明中引用表号**（如"见表3.2.1"），页面本身无表——**漏检率为 0**（在本册口径下）。
- 结构守恒：**63/73（86.3%）全过**；10 张存在结构问题，人工归因集中于两类：
  1. **续表/附录表的表头 rowspan 过声明**（如 page_0087 单行表头被声明 rs=2，致首行数据被推入幻影列）；
  2. **无横线子行的错位**（一个序号下多个构造分项各带数值、行间无分隔线，GLM 将数值对到相邻行）。
- 文本词元命中（对 RapidOCR 参照的下界口径）：73 表均值 **0.897**，p10 0.742；此前 4 页难例人工逐格核验显示真实正确率显著高于此下界。

### 8.3 缺陷清单定级（12 页签名命中，人工定级）

| 类别 | 页 | 定级 |
|---|---|---|
| 等级类列纵向合并+文本无分隔拼接（"一级二级""不限31"） | 0013/0018/0022/0029/0034/0035/0036 | **真缺陷，约 7/73 ≈ 9.6%**，可自动签名检测 |
| 表头多标签并入一格（空格分隔尚存） | 0030/0038 | 轻度缺陷，后处理可拆 |
| 签名误报（原文即汉字+数字连排） | 0031/0085/0113 等 | 非缺陷 |

**关键结论：两类真缺陷都可被自动检测**——守恒校验抓住结构类（8.2-1/2），签名正则抓住拼接类（8.3-1）。这意味着试点方案 L4 校验门可以把这些表自动挑出来，走"标记 + 二次复核（Qwen/DeepSeek 对拍或人工）"闭环，无需全量人工。

### 8.4 补测后对 Q11 的建议不变，且论据更完整

GLM-OCR 整册可用性（成功率、成本、时延、零漏检）验证通过；缺陷率有界（结构 13.7%、拼接 9.6%，有交集）且**全部可自动检测、可定向兜底**。维持建议：GLM-OCR 为主解析器 + 校验门 + DeepSeek/Qwen 对拍兜底，走需求书 v1.1 变更。
