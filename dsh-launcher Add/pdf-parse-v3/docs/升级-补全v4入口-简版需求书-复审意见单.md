## 四、轻微（Minor）

### [轻微-复审-1] 弹选的"无 TTY / 无人值守"收敛未界定（批处理存在挂起或行为歧义风险）

- **anchor**：`升级-补全v4入口-简版需求书.md` §5 R-05（"必须先弹出选择项、用户选择后才能降级"；验收要点"SKILL.md 与 CLI 均有对应口径与行为"，且明文"禁止仅'告知'即降级"）↔ §6.3 第 3 条（"必须暂停并**弹出选择项**…用户选择后方可继续——用可复测脚本断言（无选择不产出）"）↔ §4（非目标）第 1 项（"批量放 v4 补全后的下一步"）↔ 需求确定书 §3.3-2（"人工仅在失败清单层面事后介入"）。
- **basis**：对象把"整管线结构性不可跑时必须弹出选择项、用户选择后才能降级、未选择不产出"设为 **P0 硬性行为**，但**未界定在无 TTY/无人值守**（CI、cron、批处理、管道重定向）下的收敛方式。R-05 验收要点虽承诺"SKILL.md 与 CLI 均有对应口径与行为"，却**未给出该口径的具体内容**："无选择不产出"仅定义了交互态语义（弹窗无人/超时→无产出），未定义无 TTY 态是"中止＋非零退出＋整管线级 issue 留痕"，还是"阻塞等待 stdin"（可能挂起/超时），抑或其他等效行为；若实现为阻塞读取，将违反 §7"任何降级/异常…留痕（可观测性，不静默）"的意图。此残留构成 S-2.2 上轮建议处置"非交互上下文显式例外"子项**未被采纳**的后果。此外，§4-1 已把批量重转列为"v4 补全后下一步"，而上游冻结设计 §3.3-2"人工仅在失败清单层面事后介入"表明原设计预期批处理**不阻塞**——本轮"降级前弹选"对该批处理预期形成张力，对象未消解。
- **建议处置**：在 R-05/§6.3 或 SKILL.md 口径中显式声明"无 TTY 时＝中止且非零退出＋整管线级 issue/差异留痕，**未产出、不静默降级 v3.0、不阻塞等待输入**"，或将该收敛项显式列入"细化任务书定口径"并点名批处理场景。取舍：鉴于"整管线结构性不可跑"为异常边缘、且批处理为"下一步"需求，本次不判为严重；但建议在进入 Step 3 前明确，以免细化任务书把挂起漏洞带入实现。
- **confidence**：中
