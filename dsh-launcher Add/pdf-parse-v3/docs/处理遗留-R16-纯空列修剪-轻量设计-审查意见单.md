## 分级清单（阻断→严重→轻微→建议）

### 阻断

### 严重

**G-1（判据/算法自相矛盾，目标表按字面规则会被跳过）**
- anchor：设计 L17 保守跳过谓词 + L18 左移映射；对照 L25（p78 14→13 预期）、L26（85 6→5 预期）。
- basis：探针实证——p78 的 col13 内存在真实空 cell（(3,13)、(18,13)/(19,13) 等，colspan=1、文本空），page_0085 的 col5 内存在 (15,5,1,1,'')（探针 col5 covering cells n=1 即此格）。这些 cell 的 `[col,col+colspan)` 区间与"全空列集"相交，按 L17 字面谓词（"任一 cell 区间与全空列集相交 → 整表跳过"）→ p78/85 均命中跳过 → 与设计自称"p78/85 均无此情形，故可剪"直接矛盾，两个真实目标全被剪策略否决，R-16 空转。
- 补充缺口：L18 只写"对 cells 逐格 col=new_col"，未定义**完全位于被删空列内的 cell 的处置**（p78/85 的空列恰恰被这类 cell 占据）——此类格无 new_col 可映射，必须显式删除（其文本为空，删除无损）；跨空列边界的 colspan>1 格才是应触发整表跳过的情形。谓词需收紧为"colspan>1 且区间跨出空列集"（或等价"区间与空列集相交且非空列集子集"），并补删除语义。
- confidence：高（确定性探针 + 文本内部矛盾，两条修复路径任一实现都会偏离 §2/§4 断言）。

**G-2（修剪后 adapter_notes 的 holes 便签不重算，验收指标按现设计不可达）**
- anchor：设计 L14/L18（修剪只改 grid.n_cols 与 cell.col）+ §2 表（p78 holes@5→0、85 holes 变化）+ §3.2（_r15_diff 对账）+ §4（holes==0 断言）。
- basis：`table_adapter.py` L96-97 在 expand_table 阶段即产出 holes issue，L201/L208 已把 `holes@N` 写进 adapter_notes（neo 与常规两分支均如此）；`_r15_snapshot.py` L22-27/L44 的 holes 字段是**从 adapter_notes 解析**。若修剪作为 html_to_grid 内"表组装后"的后置步骤只改 cells/n_cols 而不重算/清除 holes 便签：85 的 adapter_notes 仍留 `holes@21`、p78 仍留 `holes@5` → §3.2 期望的 diff（holes 21→0 / 5→0）不会出现、§4 按便签口径的 holes==0 断言必失败；pipeline/快照下游（defect 登记、遗留清单）读到的结构诊断亦失真。设计未定义修剪后的 holes 重算与便签同步步骤（或在 expand 前剪、或重算后覆写便签）。
- confidence：高（snapshot/diff/断言三处均以 adapter_notes 为 holes 事实源，而设计未安排该便签的再生成）。
