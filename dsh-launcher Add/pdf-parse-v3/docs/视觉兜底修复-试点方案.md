# 视觉兜底修复 · 试点方案（V1，仅文档；2026-09-05 已含真实 API usage 实测钉死 token 档位）

> 状态：**讨论稿 / 待批准** —— 本文仅描述方案，**不包含任何代码改动**。
> 关联：《PDF解析输出JSON规范.md》（pdf-parse-v3 输出标准）、pdf-parse-v3 技能、GBJ16-87 第1册 v3 JSON。
> 目标：**全自动、零人工复核**地把"扫描/版式提取后无法结构化的表格"修复回 JSON；
> 原则：先用足低成本手段 → 视觉大模型**仅作兜底** → 仍失败则**诚实标记**，绝不让下游误读产生幻觉。

---

## 1. 目标与非目标

- 目标：对 v3 JSON 中"有表但结构缺失/错乱"的表格，自动 检测（定位优先 OCR box 几何规则、0 token；仅无 box 才回退视觉）→ 定位源 PDF 页 → 局部截图 → 视觉大模型修复/重建 → 自动校验 → 写回带溯源的新 JSON。
- 非目标（本试点不承诺）：无框线且已完全失真的老扫描表做到 100% 还原；整册全表重建（token 失控）；任何需要人工点选的交互。
- 硬性底线：**不可静默覆盖原文**；**识别失败必须诚实标记**，使下游模型/使用者明确"该表数据不可信"，防止幻觉扩散。

## 2. 总架构：四层降级链（全自动）

```
L1 规则/统计自检      (0 token)   → 产出 suspicious_tables[]
L2 传统 OCR / 表格模型 (廉价)     → 能解则解（如整表结构清晰）
L3 视觉大模型局部兜底  (按需计费)  → A 修补 / B 重建（最小面积、最小问题）
L4 自动校验 + 诚实标记 (0 token)  → OK / FIXED / UNCERTAIN / UNREADABLE，写回 JSON
```

规则：**L3 只在 L1/L2 判定"有结构缺失"且"裁剪可定位"时启用**；L3 输出必须过 L4；L4 不过 → 一次定向重试 → 仍不过 → 标记，不覆盖。

## 3. 前置工程前提（进入实现阶段的第一批改动，本文仅约定）

1. **行级坐标必须进 JSON**（否则"定位→裁剪"不闭环）：
   - 扫描路径（RapidOCR）：其返回本就带每行四点 box，**现被丢弃**——`rapid_ocr_pages.py` 排序时只取 `r[1]` 文本、丢 `r[0]` 坐标（改一行即可保留）→ 约定 `pages[].lines[] = {box, text}`，其中 box 为四点在渲染 PNG 像素坐标系下的坐标；
   - **box 高 ≈ 行内字高**：OCR box 的纵向跨度即文本行高，可作为该行字号的几何估计（混合行取高值）；
   - 文本层路径（pdfplumber/PyMuPDF）：已有 word/行 bbox，同约定写入；
   - 老数据无 box → 标记 `locatable=false`，走"整页 crop + 视觉先找表"的**高成本回退**（仅对极少量）。
2. **坐标变换记录**：渲染页图参数（DPI/TargetWidth/像素尺寸）与 PDF 页尺寸，统一记录，保证"JSON 内 bbox → 页图上 crop"确定可换算。
3. **多模态能力可用性**：视觉大模型 API（key/额度/型号）需在试点启动前确认；若无可用视觉模型，L3 自动降级为"诚实标记+跳过"，不阻塞全流程。
4. **表格定位 = OCR box 几何规则（0 token，2026-09-05 讨论新增）**——定位**不需要视觉**，也**不需要"认字"**：
   - 原理：表格在版式上有强几何特征，直接用 OCR 行 box（前提①保留的坐标）聚类即可判定，无需调用视觉模型：
     · **行对齐 / 列对齐**：表内多行 box 的 x 起点/终点共享稳定边界（形成列）；
     · **行距均匀**：表内相邻行 y 间隔接近（有框线/无框线老表均成立）；
     · **数字密度**：单行含 ≥2–3 个孤立数字/单位片段（表体特征，区别于正文长句）；
     · **表块上下边界**：表格首/末行与相邻正文行的行距跳变明显。
   - 输出：表块 bbox（含表头行候选、是否疑似续表）+ `locatable=true`；
   - 结论：**第一遍"定位"应完全走本规则（0 token、确定性、可校验），视觉只用于第二遍"细读"**——从而消解"整页 384 视觉定位"是否省 token 的疑问（规则定位免费）；
   - 风险：无框线且粘连严重的表行聚类可能合并/漏切 → 用 L4 校验与续表检测兜底，仍失败才回退视觉定位。
5. **截图分辨率档位实测（2026-09-05，真实 API usage 为准）**——**官方图片 Token 计算器为估算且偏低 1.2–1.5 倍，不可作为预算依据**：
   - 真实 usage.prompt_tokens 实测（deepseek-v4-flash-vision-exp）：
     · 200×300=195、250×350=195、300×300=199、384×384=199（**≤150k 面积几乎平直 ≈195–199，小图不省**——存在高 base 档）；
     · 500×400=219、500×500=243、505×505=283（**255k 处跳变 +40，tile 分档嫌疑在 ~505–512 附近**）、512×512=283；
     · 600×400=247、800×400=299、**800×800=431（封顶）**、850×850=431、1111×1111=431；
   - 结论：**单图 token 区间 ≈195–431**；**封顶在 ~800×800（431）**，>800×800 恒 431 无增益（模型预压缩至约 800 总量，超出像素进模型前已丢弃、无细节增益）；
   - **非方形行为**：500×400（200k）=219，落在同面积方形预期范围内——**按实际宽高计费，非折算成正方形**；detail=low=缩到 512×512（方形），high/original=保留原尺寸；
   - **封顶值用变量**（用户规定）：可用 vision.max_resolution（当前 ≈800×800 / 431）描述"模型输入最大分辨率"，不写死字面量，未来模型变化仅改一处；
   - **建议截图分辨率反推**（0 token，几何）：由前提①的字高估计 + 渲染参数（TargetWidth/PDF 物理尺寸）→ 推算该表字号的版面相对比例与物理尺寸 → 取"能读清字的最小档位"，且单图面积不超过 vision.max_resolution，不盲目给高分辨率；

## 4. L1 检测：JSON 自检（0 token，全自动）

对 v3 JSON 逐表（`pages[].tables`，现状多为仅 caption 或缺失）与页文本（`pages[].text`）生成候选：

| 信号              | 判据示例                                                 |
| --------------- | ---------------------------------------------------- |
| 有表题无结构          | 页文本匹配 `表\s*[\d.]+` 且附近大段数字/单位，但该页 `tables[].data` 缺失 |
| 表格被压平           | 单行内出现 ≥3 个孤立数字/单位片段（空格对齐被压成一行）                       |
| 疑似续表            | 文本含"续表 / 单位 / 序号连续"，与相邻页表头列数可对上                      |
| 数字自洽破坏          | 出现合计字样但分项之和与合计不一致（需先能粗读）                             |
| 特殊字符/符号密集       | `％ ㎡ × ≤ ≈ ±` 等大量出现且行结构乱                             |
| 版式断裂（layout 路径） | 同列 x 漂移超阈值、行 y 交叠、词空隙异常                              |

输出统一候选结构（供 L3/L4 使用）：

```json
{
  "table_id": "p84_t0",
  "page": 84,
  "caption": "表3.3.11 …",
  "source_pdf": "…-1.pdf",
  "locatable": true,
  "bbox": {"x":…,"y":…,"x2":…,"y2":…},   // 缺省则 null→整页回退
  "reasons": ["有表题无结构","疑似续表"],
  "old_text_snapshot": "…原表文本片段…"
}
```

## 5. L2 传统手段（先于视觉）

- 文本层 PDF：pdfplumber `find_tables()`/`extract_table()` 直接给 `data[][]`（本方案文档不展开实现细节）。
- 扫描件：仅当框线检测结果满足"行列可解析、数值可对齐"才采用；否则进入 L3。
- 任何 L2 成功结果同样走 L4 校验。

## 6. L3 视觉大模型兜底（按 token 计费的最小化调用）

### 6.1 两种模式（默认 A）

- **A 修补/纠错**：输入 = 局部截图 **+** 原表文本/旧 JSON；请求"逐格核对并补全为结构化 JSON"。带参考 → 更准、更省 token。
- **B 重建替换**：输入 = 仅截图；请求"识别整表为结构化 JSON"。仅在 A 不可用（原文全乱/不存在）时启用。

### 6.2 输出 Schema（要求模型严格遵循）

```json
{
  "status": "ok",                  // ok | partial | unable
  "data": [["表头1","表头2"], ["a","1"]],   // 二维，缺格用 ""；有合并需显式
  "rowspan": {"r":1,"c":0,"span":2},        // 可选：合并格描述数组
  "colspan": [],
  "header_rows": 1,
  "confidence": 0.9,               // 模型自评
  "issues": ["单元格(2,3)模糊，按上值推断"]
}
```

> 若输出不满足该结构（缺 data/行列不一致），L4 直接判失败并触发一次定向重试或标记。

### 6.3 Token 最小化

- 只对 suspicious_tables 调用；bbox 外像素不送；
- 面积预算（**实测为准**，官方计算器偏低 1.2–1.5 倍）：单图 0~150k 面积 ≈195–199 tokens（存在高 base 档，小图不省）；200k≈219；~640k(800×800)≈431 **封顶**；>800×800 恒 431 无增益；
- **单图单表**（见 §6.5）：每张表单独一次上传，不做拼接；max_tokens 全局放宽（默认 12000），防 DeepSeek 截断空 content；
- prompt 仅含："给出表中各行数据 JSON（含表头/合并/置信度）"，不附加冗长说明；
- detail 档位（参数集中化）：默认 auto；高密度小字可试 high/original（保留原尺寸、细节更真、token 更高），low（512×512）仅用于粗定位/分类级——是否用 low 需实测权衡，不默认；
- 结果缓存（按 pdf 指纹+页+表 bbox），重复运行不重复计费。

### 6.4 试点预算估算（GBJ16 第 1 册示例口径，非承诺）

- 表题 63 个（现状多为"仅 caption"）→ 预估可疑表 X（以实际自检输出为准，含续表与表格页）；
- **图像 tokens 以实测为准**（真实单表 prompt≈419–439、纯色图封顶 431），官方计算器估值偏低，不可作为预算依据；
- **输出占比更高**（输出 $0.66–1.32/M，输入 cache miss $0.22–0.44/M）：真正省成本靠 prompt 输出紧凑 JSON，而非压图像尺寸；
- 预计总量级：几十张单表图、每册数千至数万 token 内（远小于整册 OCR/视觉全页重跑）；**但 output 占大头**，需按单表 ~3000 completion + ~450 prompt 估。

### 6.5 单图单表（2026-09-05 用户定稿，替代原多表拼接）

**决策**：**每张表单独一次上传**（单图单表），不做多表拼接/红线隔离。理由（实测）：
- 红线隔离拆分本身可行（模型能识别红区、给出正确顺序与身份），但暴露真实表的新问题：**真实表 token 受内容复杂度抬高**（900×577 单表实测 prompt_tokens≈419–439，高于纯色图的封顶值）、**max_tokens 不足时 DeepSeek 截断返回空 content**，且单面板表数受限；
- **单图单表 + 足够 max_tokens 实测稳定**：同一张表3.2.1，`max_tokens=4000` 时 `finish=stop`、输出 **2940 字符完整 JSON**（表头/数字全对），`max_tokens` 过低则截断空 content；
- 单图单表无拆分错乱、无红线依赖、无面积超封顶顾虑，规避上一版多表方案的全部新增不确定因素。

**max_tokens 全局放宽 + 爆破定位（用户定稿，2026-09-05，替代旧 6000 口径）**：
- `vision.max_tokens = 12000`（参数集中化）；实测单表完整输出约 2900+ 字符，12000 为大多数表留足余量，避免常爆；
- **仅当"仍爆"**（`finish_reason == "length"`，或 content 空但已计费）：**不自动重试、不分块、不降级输出**，而是**如实记录问题定位**供后续核查：
  - 记录字段（写入修复报告/单独日志）：`table_id`、`page`、`caption`、`source_pdf`、`prompt_tokens`、`completion`（是否触到 max_tokens 上限）、`finish_reason`、该表是否属续表/超大表；
  - 该表标记 `status=unreadable` + `reason="output_length_exceeded"`，**保原文不覆盖**（A1/A5）；以区别于"识别失败"原因，便于后续核查与定向重跑；
  - 生成"爆破表清单"（表号/页/原因），供人工或后续换更强模型定向重跑。
- **原则**：宁可"这一张没读到 + 留下完整定位"，也不为读取而牺牲诚实性/引入分块重试的复杂度；爆破是**少数异常**，用定位兜住而非复杂化主流程。

**单表流程**：
- 每张 suspicious_table 单独 crop → 单独一次请求 → 单独校验 → 写回该表；
- 多表页面逐张批处理（可串行/有限并行，不受"一图多表"输出容量限制）。

**prompt 模板（写入实现，参数集中化）**：
```
这是单张规范表格。请输出完整 JSON 数组（[表头行, 数据行...]），
数字照抄、缺格用空串；不要省略数据行。
```

**实测结论（写入方案，2026-09-05）**：
- 纯色图：≤150k 面积 ≈195–199（高 base 档，小图不省）；800×800 封顶 431；>800×800 恒 431 无增益；
- 真实表：900×577 单表 prompt_tokens≈419–439——**明显高于纯色图同规格**，token 随内容复杂度上升，预算**不可**用纯色图封顶值推算；
- output 才占大头：单表 completion≈2940（远高于 prompt 419）——**成本主要由输出主导，压图像尺寸几乎不省钱，管控输出格式才是关键**。

## 7. L4 自动校验与诚实标记（0 token，强制）

校验规则（对 L2/L3 输出统一执行）：

1. 结构校验：`data` 各行长度一致（含合并展开后）、非空行数>0；
2. 表头匹配：与相邻页/续表表头列数一致（跨页续表允许合并）；
3. 数值自洽：合计行 = 分项和（在可解析时）；序号连续；单位不串位；
4. 与页原文交叉：关键数字能在 `pages[].text` 或 L3 参考文本中找到（防幻觉数值）。

标记协议（写入 JSON，防下游误用）：

```json
{
  "status": "ok | fixed | uncertain | unreadable",
  "method": "pdfplumber | rapid-table | vision-A | vision-B",
  "confidence": 0.0–1.0,
  "verified_by": ["row_consistency","sum_check"],
  "issues": ["…"]
}
```

- `ok/fixed`：可正常使用；
- `uncertain`：部分格存疑 → 仅该格打标，禁止下游引用该格数值做硬结论；
- `unreadable`（含视觉拒识/重试仍失败）→ 整表 `status=unreadable`，**附 reason**，`data` 保留空或原文本引用；
- **读取方约定（写入文档+未来提示词）**：凡 `tables[].status != ok/fixed`，大模型不得把它当作事实参与计算/检索结论；引用时必须声明"该表不可信/未知"。

## 8. 全自动闭环（运行一次即完成，无人介入）

```
输入 v3 JSON → L1 自检 → suspicious_tables[]
→（locatable? bbox 换算 crop：渲染页图；bbox 优先由前提④ OCR box 几何规则产出，仅 locatable=false 才回退整页视觉定位）
→ L2 尝试 → 通过→L4
→ 否则 L3（A/B，限 1 重试）→ L4
→ 写回：新增/更新 tables[].data + status/method/confidence/issues + 保留原 text
→ 输出：修复报告（每表：路径、结果、token 数、校验项）
→ 失败清单（uncertain/unreadable）单独汇总，供未来换更强模型重跑（仍无需人工）
```

## 9. 风险与缓解

| 风险           | 缓解                                            |
| ------------ | --------------------------------------------- |
| 视觉幻觉数值       | L4 数值自洽+原文交叉校验；不通过→标记而非覆盖                     |
| 无框线老扫描表      | 承认上限：uncertain/unreadable 诚实标记为常态可接受          |
| 坐标/渲染不一致导致裁错 | 前提工程统一坐标变换；裁错→回退整页（限次）                        |
| 多模态不可用/超预算   | L3 自动跳过并标记；预算上限参数可配（如每册 max_calls/max_tokens） |
| 下游误用         | 文档+约定：非 ok/fixed 不得当事实；模型调用前注入该读取规则           |
| max_tokens 截断误判    | 单表 max_tokens 全局放宽（默认 12000）；先判 finish_reason==length 为输出超长而非识别失败，据实定位记录（reason=output_length_exceeded），不自动重试也不降级 |
| 真实表 token 高于封顶   | 预算按实测（真实表 prompt≈450、completion≈3000/单表），不用纯色图封顶值推算；单表独立评估 |

## 10. 试点验收（无人复核，用指标说话）

- 覆盖率：suspicious_tables 中"可定位+可调用视觉"的比例；
- 自动校验通过率：L4 全过（ok/fixed）占比；
- 诚实标记率：uncertain/unreadable 占比及 reason 完备率；
- 成本：每表平均 token、每册总 token；
- 溯源完整率：每表含 method/status/confidence/issues。
- 抽检（可选、仅统计）：对 fixed 表做数值回读一致性统计，不要求人工点选。
