## 四、建议级

### 建议-1　R-05 _parse_pages 先并集后交集，合法但超大的 range token 可致 set 膨胀失控

- **anchor**：对象 §2 R-05 代码（L109-117 `out.update(range(a, b + 1))` 在取交集前全量展开）。
- **basis**：token 全合法但段界巨大（如 "1-9999999999"）时，并集 set 展开 O(10^10) 元素后才与 [1,page_count] 求交；3 页 PDF 本应"交集空→报错"，却先耗尽内存。建议逐段先与 [1,page_count] 截交（或对单段上界设限）再入集，语义不变且稳健。属本地输入稳健性，非行为语义缺陷。
- **confidence**：high（range 展开大小与内存关系确定性）。

### 建议-2　R-13 仅以"数相等/数不等"判定配对，数等而序错（跨语料）无探测、将静默错配 bbox

- **anchor**：对象 §2 R-13 产品（L283-290 仅 count 等即 zip 配对、不等整页退化）、预研（L261 本机夹具 180/180）、§8 诚实声明（L362）。
- **basis**：预研只证本机夹具语料序一致（order_ok=180）；生产跨语料若"md 表序 ≠ layout 块序且 count 相等"，逐位 zip 会把错误 bbox 配给表（比退化 bbox 更隐蔽：真实但错误区域的 bbox 喂 gate/crop/second 出错误坐标），而兜底仅"数不等"分支。Step-3 审查意见单建议-1 曾提示"发现错位改内容匹配（可哈希/首格比对）"。建议：count 相等路径加低成本首格/内容哈希一致性探测，失配转整页退化+note；或在设计内显式记录"序错无探测"为残余风险（现诚实声明只覆盖语料范围，未覆盖序错探测缺位）。
- **confidence**：medium（跨语料序错概率不可测，机制缺口为推演）。

### 建议-3　R-07 m-05 复算断言近乎恒真（同一派生式双写），防不了"scale 与实渲像素漂移"

- **anchor**：对象 §2 R-07 断言尾（L182 `abs(reg["dpi"] - round(reg["target_width"]*72/pdf_w,2)) <= 0.5`）。
- **basis**：分支 B 登记 dpi=round(tw*72/pdf_w,4)（L177 传入即同式），断言用同一 tw 与同一 pdf_w 回算 round(…,2)，|round(x,4)−round(x,2)|≤0.005<0.5 恒成立——该子句对任何"dpi/tw 同源登记"实现恒绿；m-05 的物理口径（dpi 与实渲 pixel 宽度自洽）实际由现存 test_render ③（pixel 回算）承载。属弱断言非空转（若 dpi/tw 被记成互斥值仍会红），但作为 ⑦ 的"m-05 复核"子句名不副实。
- **confidence**：high（公式双写推演确定性）。

### 建议-4　R-14 文档同步表的表头时点与表内 SKILL.md 行时点冲突，易误导 Step 9 执行人

- **anchor**：对象 §2 R-14 表头（L301"（Step 9 执行）"）与表内 SKILL.md 行（L306"随 R-10 代码同批，否则 ci_all 反向校验红"）；§5（L342-343 SKILL/ci_all 归 Step 7、冻结文档修订注归 Step 9）。
