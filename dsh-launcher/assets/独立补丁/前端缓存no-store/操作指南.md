# 前端缓存 no-store 补丁 · 操作指南

> 本补丁自 2026-11-06 起**脱离启动器的自动装载体系**，独立存放。
> 原补丁引擎与自动载入清单已退役（归档在 `D:\DSHS\_bak\补丁管理-退役-<时间戳>\`）。
> 平时不生效、不会被任何流程自动安装。需要时才手动处理。

## 一、它解决什么

DSH 前端是 client-plugin 图：`index.html` 里嵌了本次启动动态生成的插件清单（带 rev 哈希）。
浏览器一旦复用旧的 `index.html`，就会拿新插件去配旧文档，表现为：

- 侧边栏白屏 / 界面加载不出来
- 控制台报 `client-modules: boot manifest batches must be an array`
- 升级或重建前端后，必须反复硬刷新才恢复

补丁改的是**静态资源缓存策略**三档：

| 资源 | 策略 |
|---|---|
| 渲染的 `index.html` | `no-store`（永不缓存） |
| 文件名带内容哈希的资源 | `public, max-age=31536000, immutable` |
| 其余（favicon、web manifest、未哈希文件） | `no-cache` + ETag，命中 `if-none-match` 回 304 |

补丁**只覆盖构建产物** `@deepseek-ai\dsh-host-frontend-static\lib\index.js`，不碰 TS 源码，不占 git 工作树。

## 二、什么时候才需要

三个条件同时成立才动它：

1. 升级 / 重建前端之后出现白屏或上面那条 `boot manifest batches` 报错；
2. 硬刷新（Ctrl+F5）能恢复，但不刷新就复现——说明确实是缓存问题；
3. 确认当前版本的上游仍未修掉这个问题。

任何一条不成立就别装。**它是补丁，不是功能。**

| 文件 | 作用 |

## 四、两个脚本的运行前提（重要，别看错）

它们原本由已退役的引擎驱动，靠引擎注入三个环境变量：

- `DSH_PATCH_PROFILE_DIR` —— profile 的 node_modules（0.1.x 布局）
- `DSH_PATCH_BACKUP_DIR` —— 本次备份目录
- `DSH_PATCH_DSH_ROOT` —— DSH 根（0.2.x 布局）

**直接双击/直接跑会失败**，因为它们没有自己解析这些值。它们是**参考实现**，不是一键安装器。
正确的用法是：把本目录连同《给agent的提示词.md》交给 agent，由它按当前版本改写。

## 五、换版本怎么重做载荷

1. 在源码树里 `git checkout` 回上游干净的 `packages/host/frontend-static`；
2. 应用 `源码增量-前端缓存no-store-0.2.1-rc.2.patch`（可用 `git apply`，冲突就按上下文手工套）；
3. 构建：`pnpm run build:lib:host`（或项目对应的构建命令）；
4. 取构建产物 `lib/index.js` 覆盖 `载荷文件\...\lib\index.js`；
5. **把源码树还原干净**（`git checkout`），别让增量留在工作树里挡住下次 `git pull`；
6. 在 `操作指南.md` 里把这个补丁的"对应版本"和载荷大小一起更新。

## 六、怎么验证生效

活服务上跑（本机已有工具）：

```powershell
node %USERPROFILE%\.agents\skills\dsh-launcher\assets\tools\test-frontend-cache.mjs
```

期望：index 返回 `no-store`；带哈希资源返回 `immutable`；普通资源 `no-cache` + ETag，且带 `if-none-match` 的条件请求回 304。
历史上按此 7/7 通过（no-store / immutable / no-cache+etag / 304 / 旧 etag 仍 200 / 越界 403 / 缺失 404）。

## 七、怎么还原

`还原脚本` 依赖备份清单（`backup-manifest.json`）。备份默认落在 `%DSH_HOME%\patches-backup\<补丁id>\`
（本机为 `C:\Users\雍远\.dsh\patches-backup\dsh-frontend-static-no-store\`，内含 3,899 B 的原版 `index.js`）。

没有备份清单时，最稳的还原方式是**重装该包**：升级一次 DSH 版本，或 `pnpm install` / `npm i` 让包回到上游原状。

## 八、铁律

1. 装之前先秒级备份目标文件，并写下回滚命令。
2. 只覆盖构建产物，绝不覆盖 TS 源码。
3. 装完必须重启 `dsh web`，再硬刷新浏览器。
4. 版本对不上就别硬装——换版本要先重做载荷（第五节）。
5. 装错的表现是前端渲染异常（历史故障：会话历史加载失败、消息无反馈，但 RPC 直连正常），极难排查；一旦出现，按第七节还原。
