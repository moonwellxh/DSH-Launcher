# 档案柜 v2 · 源码增量留档与重放说明

本目录记录「档案柜 v2（恢复半边）」在 DSH 源树里的**源码改动**，用于：
DSH 升级后需要重新适配本补丁时，作为「当初怎么改的」的权威参照（补丁载荷只是构建产物）。

## 文件

- `源码增量-档案柜v2.patch`：`git diff` 出来的 tracked 改动（16 个文件：4 个服务端/契约 + 4 个客户端 + 6 个测试/测试替身 + …）。
- `源码增量-新增文件\`：新增源文件的副本（`ArchiveBin.tsx` / `ArchiveBin.module.css`），按原路径镜像存放。

## 为什么源树里没有这些改动

补丁只覆盖**构建产物**（`@deepseek-ai\...\lib\*.js`）。源码改动若长期留在工作区，
会阻挡 DSH 升级第一步的 `git pull`（本地改动与上游冲突）。因此安装本补丁时：
源树已 `git checkout` 回上游原状，功能由载荷提供。

## 重放/重新适配步骤（DSH 升级后）

1. 在工作区 `git apply 源码增量-档案柜v2.patch`，并把 `源码增量-新增文件\` 里的文件按原路径放回流源树；
2. `pnpm install`（如需）→ `pnpm run build:lib:host` → `pnpm run build:lib:client`；
3. 把新构建的 6 个产物重新抽成本补丁的 `载荷文件\`（清单见 `安装脚本-档案柜v2.ps1` 的 `$files`）；
4. 更新清单里本补丁的 `compatibleDsh` 为新版本，再跑 `补丁引擎-应用还原检查.ps1`；
5. 再次把源树恢复干净（`git checkout -- <改动文件>` + 删除新增文件）。

> 注意：`tsc -b tsconfig.client.json` 会一并类型检查 `tests/` 与 `test-support/`，
> 新增 Remote 方法/IWorkspaces 方法会加宽生成接口并打到所有 fake，
> 所以 patch 里那 6 个测试面改动是**构建必需**，不是可选项。
