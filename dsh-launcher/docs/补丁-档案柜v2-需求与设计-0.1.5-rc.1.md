# 档案柜 v2（恢复半边）· 需求与设计（DSH 0.1.5-rc.1）

- 日期：2026-09-12
- 背景补丁：`assets\补丁管理\补丁01-档案柜v1-归档升级版`（id `dsh-recycle-bin-v1`，`compatibleDsh=["0.1.1-rc.2"]`，现 `enabled=false` 挂起）
- 判定依据：`D:\DSHS\升级\dsh-launcher-兼容性分析报告-0.1.5-rc.1.md` §4 + 本机实测复核（2026-09-12）

## 1 为什么要重做（v1 不可用的三条硬事实，逐条已实测）

| # | 事实 | 证据 |
|---|---|---|
| 1 | v1 载荷是 **整文件覆盖旧构建产物**，绑定 0.1.1-rc.2 | 载荷 5 个 `.js` 与备份原件逐字节属于旧构建；新版客户端连接层大改（新增 `browser-auth.ts`、删除 `websocket-downlink.ts`） |
| 2 | v1 的 5 个目标包里 **2 个包已被上游删除** | `@deepseek-ai\dsh-client-runtime`、`@deepseek-ai\dsh-host-apiproxy` 在 profile 里是**悬空 junction**（target 不存在）→ 引擎 `Install-PatchedFile` 会因「目标目录不存在」直接抛错 |
| 3 | v1 的功能**已被上游原生取代大半** | 原生已有：`workspaceRegistry.archivedSessionIds`、RPC `workspace/archiveSession`、客户端 ⋯ 菜单「归档会话」（`ui-workspace/src/client/locales.ts`）。**仍缺**：查看已归档会话的入口 + 恢复（`restoreSession` 全库无此符号，侧边栏无档案柜分区） |

## 2 目标与非目标

**目标**：在 0.1.5-rc.1 上恢复「档案柜」能力——① 能看到已归档会话；② 能把其中任意一条**恢复**回原分组（原会话位次保留：上游注释明确 archived session keeps its `sessionIds` slot, so unarchiving restores its position）。

**非目标**：不重复实现「归档」入口（用上游原生 ⋯ 菜单「归档会话」）；不改动主列表 `WorkspaceBrowser.tsx` 的既有渲染逻辑；不做会话删除/彻底清理。

## 3 技术设计（源树增量 → 重建 → 抽载荷 → 补丁引擎安装）

### 3.1 服务端（`C:\Users\雍远\deepseek-harness`）

| 文件 | 改动 |
|---|---|
| `packages/workspace/workspace/src/index.ts` | 新增 `restoreSession(sessionId: SessionId): Promise<void>`：从 `requireState().archivedSessionIds` 中移除该 id（不在集合内则直接返回，幂等）；`await this.setState({ ...state, archivedSessionIds: next })`。写 state 会驱动既有 `{ type: 'archived', archivedSessionIds }` 增量广播，客户端无需新增事件类型 |
| `packages/api/workspace-controller/src/types.ts` | 新增 `WorkspaceRestoreSessionRequest { readonly sessionId: SessionId }`；结果复用 `WorkspaceArchiveValue`（完整归档集合） |
| `packages/api/workspace-controller/src/commands.ts` | 新增 `restoreSession(request)`，调用 registry 的新方法 |
| `packages/api/workspace-controller/src/index.ts` | 新增 `@Remote('restoreSession')`（端点 `workspace/restoreSession`） |

构建后 typert 会自动重新生成 `lib\typert.host.js` / `lib\typert.remote-client.js` 里的描述符——**这是新增 Remote 的必要产物，必须在载荷里一起覆盖**。

### 3.2 客户端（`packages/client/ui-workspace/src/client`）

选点：**注册到既有空扩展点 `sidebar.footer.action`**（`kind: 'list'`，owner props `{ wide }`，由 `ui-sidebar` 声明、当前无占用者），而不是改 60KB 的 `WorkspaceBrowser.tsx`——把改动面收敛在一个新组件内。

| 文件 | 改动 |
|---|---|
| `contract/slots.ts` | `WorkspaceBrowserInjected` 增加 `restoreSession: (sessionId: SessionId) => Promise<void>`；为 footer 注册声明注入面类型 |
| `navigation.ts`（`UiWorkspaceService`） | 增加 `restoreSession(sessionId)`：调 `workspaces.restoreSession(sessionId)`（remotes 客户端） |
| `ArchiveBin.tsx` + `ArchiveBin.module.css`（新增） | 侧边栏底部「档案柜」入口：宽栏渲染一行（含已归档条数徽标），窄栏渲染图标；点击展开/弹出面板列出已归档会话（标题 + 最近更新时间 + 恢复按钮）；空集显示「暂无归档会话」；每条恢复成功后自行从列表移除（状态由 `archivedSessionIds` 快照驱动）。已归档会话的标题/时间从 `sessions` 快照取（与 `WorkspaceBrowser` 同一数据源） |
| `index.ts` | `ctx.slots.inject('sidebar.footer.action', () => ctx.slots.register({ name:'sidebar.footer.action', id:'archive-bin', order:0, locale: NS, inject: ... }, ArchiveBin))`；沿用现有 `NS='workspace'` 字典 |
| `locales.ts` | 新增键：入口名、面板标题、空态、恢复按钮、恢复中、失败提示（中英各一份） |

## 4 验收（可复跑）

| 项 | 判据 |
|---|---|
| 构建 | `pnpm run build:lib:host` 与 `pnpm run build:lib:client` 均 exit 0 |
| 产物含新符号 | `dsh-api-workspace-controller\lib\typert.host.js` 含 `workspace/restoreSession`；`dsh-client-ui-workspace\lib\client.js` 含恢复相关文案与 `restoreSession` |
| RPC 端到端 | 用启动令牌换 cookie 后：`workspace/archiveSession` 归档一条测试会话 → `session/list` 中该 id 出现在 `archivedSessionIds` → `workspace/restoreSession` → 归零；测试会话与临时工作区测后清理 |
| 界面 | 重启 dsh web 后侧边栏底部出现「档案柜」入口；归档一条会话后入口计数 +1，点开可见并可恢复（**需人工目视确认**） |
| 回滚 | `补丁引擎-应用还原检查.ps1 -Restore` 可还原到上游原状 |

## 5 风险与诚实声明

- 载荷绑定 0.1.5-rc.1；DSH 升级后必须重新适配（与 v1 同性质）。
- 客户端 UI 属新增代码，构建通过≠界面一定正确；界面需人工目视确认（无自动视觉回归）。
- 若上游后续原生实现 restore，应停止叠加本补丁（退出条件）。
