# 日志与留痕 · 维护说明（dsh-launcher）

> 面向：后续维修本启动器的 agent / 人。**动手改托盘提示或硬重启逻辑之前，先读本文件。**
> 制定依据：`coding-log-monitor` 技能（档位判定＝MVP→生产之间的本地常驻服务；详见文末偏离声明）。
> 最后更新：2026-10-26。

## 1 一句话现状

托盘的**所有提示**是右下角自绘卡片（瞬时、不进通知中心），**每张卡片都会自动写一行**到
`<安装目录>\dsh-tray.log`；「硬重启托盘」另外记 `restart.start` / `restart.setup` 两行。
读日志用 `<安装目录>\dsh-log.ps1`，不要自己写解析。

## 2 文件

| 文件 | 谁写 | 说明 |
|---|---|---|
| `<安装目录>\dsh-tray.log` | `dsh-toast.ps1`（每张卡片）、硬重启 helper（两个事件） | 主日志。UTF-8 无 BOM，一行一条记录 |
| `<安装目录>\dsh-tray.log.1` | 轮转产物 | 主日志超过 1 MB 时改名，只保留 1 份（无 .2/.3） |
| `%TEMP%\dsh-tray-fallback.log` | `dsh-toast.ps1` / 硬重启 helper | 主日志写不进时的降级落地（首行 `event=log.fallback` 带失败原因） |
| `<安装目录>\dsh-web.log` / `.err.log` | 被托盘的 `dsh web` 服务 | DSH 服务自身日志，与本日志无重叠，不要混看 |
| `<安装目录>\dsh-restart-status.txt` | 硬重启 helper | 一次性交接文件：新托盘读到就删（不是长期日志） |

## 3 记录格式（一行一条，固定前缀，可被正则解析）

```
[dsh-tray] ts=2026-10-26T00:54:38.641+08:00 level=INFO event=restart.start run=e2afcdf6 old_tray_pid=999999 setup_path="C:\...\setup.ps1"
[dsh-tray] ts=2026-10-26T00:54:41.664+08:00 level=INFO event=restart.setup run=e2afcdf6 state=done exit="0" duration_ms=3012 notes=""
[dsh-tray] ts=2026-10-26T00:54:36.557+08:00 level=ERROR event=notify src=card pid=24544 title="DSH 硬重启结果" text="安装脚本=failed（退出码 3）；…"
```

约定：
- `ts`＝ISO8601 本地时间带时区偏移（`yyyy-MM-ddTHH:mm:ss.fffzzz`），毫秒可比对。
- 值含空格/中文一律用双引号包住；值内双引号替换为单引号、换行折成空格（**不用转义，便于 grep**）。
- 事件类型（`event=`）目前只有三种，新增事件请在此表补一行：

| event | 写入者 | 字段 |
|---|---|---|
| `notify` | `dsh-toast.ps1` | `src=card`、`pid`、`title`、`text`、`level`（按卡片 Kind 映射） |
| `restart.start` | 硬重启 helper | `run`（8 位关联 ID）、`old_tray_pid`、`setup_path` |
| `restart.setup` | 硬重启 helper | `run`（与 start 相同）、`state=done\|failed\|timeout\|missing`、`exit`、`duration_ms`、`notes` |
| `log.fallback` | 写入失败时 | `sink=temp`、`primary`、`error`；主日志那一行跟在下一行 |
| `log.rotate_failed` | 写入时 | `primary`、`error`（轮转失败仍继续写，只是不滚动） |
| `status.write_failed` | 硬重启 helper | `path`、`error`（`dsh-restart-status.txt` 写不进去） |
| `ui.noactivate_fallback` | 卡片启动时 | `error`（不抢焦点编译失败，退化成普通窗口） |
| `log.singleinstance_failed` | 卡片启动时 | `error`（pid 文件登记失败，可能两张卡片） |

## 4 级别语义（与技能 H17 的差异见 §7）

- `INFO`：生命周期事件（提示弹出、硬重启开始/成功）。
- `WARN`：非致命但需知晓（`restart.setup` 的 failed/timeout/missing、对外告警类提示）。
- `ERROR`：阻断性失败（对外 Error 级提示，例如"打开 Web UI 失败"）。

## 5 怎么读（不要自造解析）

```powershell
# 最后 30 条（默认，已按事件类型排版）
powershell -NoProfile -File <安装目录>\dsh-log.ps1
# 只看告警/错误
powershell -NoProfile -File <安装目录>\dsh-log.ps1 -Level WARN,ERROR
# 只看硬重启
powershell -NoProfile -File <安装目录>\dsh-log.ps1 -Event restart.start,restart.setup
# 统计（各级别、各事件条数）
powershell -NoProfile -File <安装目录>\dsh-log.ps1 -Summary
# 原样（要 grep 全部 key=value 时）
powershell -NoProfile -File <安装目录>\dsh-log.ps1 -Raw -Tail 5
# 连同 %TEMP% 降级日志一起看（主日志不可写时才有内容）
powershell -NoProfile -File <安装目录>\dsh-log.ps1 -IncludeFallback -Tail 20
# 直接 grep 也行（前缀与字段名稳定）
Select-String -Path <安装目录>\dsh-tray.log -Pattern 'level=ERROR|event=restart.setup'
```

## 6 改代码时的硬约束

1. **不要直接调 `$notify.ShowBalloonTip`**：本机 `EnableBalloonTips=0`，气泡不显示，且不留痕。
   一律用 `Show-DshNotice 超时 标题 正文 Info|Warning|Error`（10-utils.ps1），它会启动
   `dsh-toast.ps1` 并由其写日志。
2. 新增提示若绕过 `dsh-toast.ps1`，必须自己按 §3 格式追加一行，否则"卡片有、日志无"。
3. 新增 `event=` 必须同步本文件 §3 的表，否则后续 agent 解析不到。
4. 日志写入必须是**非阻塞、失败不影响功能**（写不进去也不能让托盘崩）。
5. 不要把令牌/路径敏感信息写进 `text`（当前会写完整消息正文，含安装路径；这是本机内网自用，
   如需外发请看 `dsh-sync.ps1` 的 `Is-SyncIgnored`，日志文件本身不进包）。

## 7 偏离声明（技能 §3 例外出口四要素）

| 偏离 | 为什么 | 影响面 | 替代观测 |
|---|---|---|---|
| 不用 JSON Lines，用 `key=value` | 读者是人＋agent，终端里直接看；JSON 在控制台不可读 | 需自写正则；已提供 `dsh-log.ps1` 统一解析 | 结构化脚本解析 |
| `WARN` 用于"非致命但需知晓" | 本托盘没有"重试后成功"这类自愈事件 | 级别语义与技能表略有出入，已在 §4 声明 | — |
| ~~写日志失败时静默~~ → **日志路径已无空 catch**（2026-10-26 修订） | 提示是主功能，日志是旁路；但"静默丢"不可接受 | 主日志不可写时整条记录转 `%TEMP%\dsh-tray-fallback.log` 并留 `event=log.fallback`（含异常类型与消息）；两处都写不进时内存计数 + `Write-Warning` 到宿主 stderr | 降级日志 / 计数 / stderr |
| 无关联 ID 透传（H11） | 卡片与日志 1:1，硬重启两行用 `run` 关联 | 无跨进程链路追踪 | `run` 字段 |
| 无指标/告警（H16） | 本地单用户启动器，无采集端 | 无法做趋势告警 | `dsh-log.ps1 -Summary` 人工看计数 |
| 无自动体检（H19） | 未提供；诊断仍靠 `dsh-log.ps1`＋`dsh-web.log` | 需人工判断 | 见 §5 |
