# DSH 一键启动 - 环境要求与安装指南

> 适用：在任意一台新机器上安装 DSH 一键启动（dsh-launcher）之前，先按本文装好环境。
> 本机实践沉淀（2026-08-30）。

---

## 一、需要的环境（总共 2 个运行时）

| 运行时               | 版本要求            | 用途                                |
| ----------------- | --------------- | --------------------------------- |
| **Node.js**（通用安装） | LTS 即可（如 v24.x） | 运行 DSH 本体（dsh web / TUI）与托盘脚本     |
| **Git**（通用安装）     | 任意较新版本          | 托盘「一键同步」/ DSH 升级（dsh-sync.ps1 依赖） |

> ⚠️ **只用这 2 个，且必须"通用"安装**——见第二节。

---

## 二、为什么必须"通用"安装（重要）

DSH 启动器（托盘脚本）启动 web 服务前，会**清理宿主 agent 注入的环境变量**：

- 移除 PATH 中 `kimi-desktop` / `daimon` / `kimi-work` 段（宿主应用注入的私有运行时路径）
- 删除 `npm_config_prefix`（可能被指向宿主私有 npm 全局目录）
- 删除 `GIT_CONFIG_*`（宿主注入的残缺 git 配置变量，会导致 git 报 `missing config key`）

**后果**：如果机器上只有宿主应用内嵌的 node/git（如 kimi-desktop 的
`...\resources\resources\runtime\node.exe`），清理后 PATH 里就没有任何 node/git →
托盘启动失败 / 同步报「未找到 git」。

因此：**机器上必须存在独立的通用 Node.js 和 Git**。禁止依赖任何桌面应用内嵌运行时。

---

## 三、安装 Node.js（免管理员，用户级）

1. **下载**官方 LTS 压缩包（二选一）：
   - 官方：`https://nodejs.org/dist/latest-v24.x/` → 选 `node-vXX.X.X-win-x64.zip`
   - 国内镜像（推荐，更快）：
     `https://registry.npmmirror.com/-/binary/node/latest-v24.x/`
2. **解压**到用户目录，例如：`%LOCALAPPDATA%\Programs\nodejs`
3. **加入用户 PATH 并置首**（PowerShell）：
   
   ```powershell
   $dir = "$env:LOCALAPPDATA\Programs\nodejs"
   $up = [Environment]::GetEnvironmentVariable('Path','User')
   [Environment]::SetEnvironmentVariable('Path', "$dir;$up", 'User')
   ```
4. **验证**（新开终端）：
   
   ```powershell
   node -v    # 期望 v24.x（LTS）
   npm -v
   ```

> 也可用官方 MSI 安装到 Program Files（需管理员），效果相同。

## 四、安装 Git（三选一）

| 方式                        | 说明                                                                                                                                                                                                    |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Git for Windows 官方安装器** | 装到 `C:\Program Files\Git`，自动加入系统 PATH（需管理员）                                                                                                                                                           |
| **MinGit（精简版，推荐免管理员）**    | 下载 `MinGit-<版本>-64-bit.zip` 解压到 `%LOCALAPPDATA%\Programs\MinGit`，把其 `cmd` 目录加入用户 PATH。镜像：`https://registry.npmmirror.com/-/binary/git-for-windows/`（如 `v2.55.0.windows.5/MinGit-2.55.0.5-64-bit.zip`） |
| **本机已有 Git**（如 `D:\Git`）  | 已在 PATH 即可，跳过安装                                                                                                                                                                                       |

**验证**（新开终端）：

```powershell
git --version
```

> `dsh-sync.ps1` 内置 **git 兜底探测**：若运行时 PATH 找不到 git，会自动探测
> `C:\Program Files\Git\cmd`、`%LOCALAPPDATA%\Programs\MinGit\cmd`、
> `%LOCALAPPDATA%\Programs\Git\cmd`、GitHub Desktop 内置 git，找到即补入 PATH。
> 所以即使 PATH 配置不完整，同步功能也能自愈。

## 五、干净启动（关键概念）

**环境是否干净，取决于"谁启动的"：**

| 启动方式                                           | 环境                                       |
| ---------------------------------------------- | ---------------------------------------- |
| 双击桌面「启动DSH」快捷方式 / `启动DSH-托盘.vbs`（explorer 冷启动） | ✅ **干净**：注册表 PATH 完整（含通用 node/git），无宿主注入 |
| 开机自启（启动文件夹 / 注册表 Run）                          | ✅ 干净（登录时 explorer 拉起）                    |
| 从宿主应用内部启动（如 kimi 桌面应用里拉起 DSH）                  | ⚠️ 继承宿主注入环境（托盘脚本会清理，但不彻底刷新注册表）           |

**重要规律**：

- 托盘「重启 DSH」按钮 = 新托盘**继承旧托盘当前环境**（进程环境传递），**不会重新读取注册表**
- **修改注册表 PATH 后（如新装 Node/Git），必须冷启动**（退出托盘 → 双击「启动DSH」/vbs），新进程才会读到新 PATH
- 建议日常启动统一用桌面「启动DSH」快捷方式

## 六、配置 GitHub token（同步/上传用）

只有「上传/同步」需要 token（push 必须有写权限）；仓库公开后「拉取/检测」匿名即可。

**新机器一键配置**：本技能自带 `assets\configure-git-credentials.ps1`，运行后
**安全输入 fine-grained token（输入过程不显示）**，自动完成：① git credential approve
（push 用）② 写入 `~\.dsh\gh-sync\config.json`（同步用）③ 可选连通性测试。

```powershell
powershell -ExecutionPolicy Bypass -File "<技能目录>\assets\configure-git-credentials.ps1"
```

token 创建：GitHub → Settings → Developer settings → Personal access tokens →
Fine-grained tokens → Repository access 只选本仓库（如 moonwellxh/DSH-Launcher）→
Contents: Read and write。

**安全红线（分发必守）**：
- token 只存本机 `~\.dsh\gh-sync\config.json`（在技能目录之外），**绝不放入技能目录**
- dsh-sync 打包/上传内置凭证类文件通配排除（`Is-SyncIgnored`：config.json / credentials /
  .dsh / *.token），即使误放技能目录也会被自动拦截，**绝不会打包进 zip / 上传到 GitHub**
- 仓库公开后，其他用户拿到的是不含任何凭证的代码；他们的检测走匿名访问，无需 token
## 七、安装后验证清单

新开一个干净终端，逐项确认：

```powershell
node -v                          # 期望 LTS（如 v24.20.0）
npm -v
git --version
(Get-Command node).Source        # 期望通用 node 路径（如 ...\Programs\nodejs\node.exe），非应用内嵌
(Get-Command git).Source         # 期望通用 git 路径
"$env:npm_config_prefix"         # 期望为空
"$env:GIT_CONFIG_COUNT"          # 期望为空
```

**托盘环境健康检查**：托盘启动后，右键第三行「一键同步」应能直接成功
（会显示「已上传/已是最新」或正常弹窗，而不是「未找到 git」）。

## 八、网络与代理

- **下载**：优先官方源直连；失败用国内镜像 `registry.npmmirror.com`（node / git-for-windows 都有）
- **DSH 同步/升级**：`dsh-sync.ps1` 自动探测系统代理（读注册表 IE 代理）并直连↔代理双路回退；git push 使用 `~\.dsh\gh-sync\config.json` 里的 token（仅内存注入，不落盘）

## 九、常见问题速查

| 症状                                          | 处理                                                                                               |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 托盘启动后 web 起不来 / 「反复启动失败」                    | 检查托盘脚本渲染的 node 路径是否为**真 node.exe**（`setup.ps1` 的 Find-Node 已自动排除 agent 包装器 node.cmd）；确认已装通用 Node |
| 同步报「未找到 git」                                | 装 Git（见第四节）；`dsh-sync.ps1` 有兜底探测，多数情况自愈                                                          |
| git 报 `missing config key GIT_CONFIG_KEY_0` | 宿主注入残缺 `GIT_CONFIG_*` 变量；托盘/dsh-sync 已自动清理，无需手动处理                                                |
| `node -v` 显示的是应用内嵌版本                        | 该终端被宿主注入 PATH；换干净终端，或冷启动托盘                                                                       |
| 修改 PATH 后托盘仍找不到新装的 node/git                 | 进程链环境继承旧值；必须冷启动（退出托盘后重新双击「启动DSH」）                                                                |
